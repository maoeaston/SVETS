# /vibe-feature — 新功能定义与 Mini-PRD

## 目标

把尚未形成正式设计的新需求，转换为一份基于当前权威资料、边界明确、可验收、经过独立审查的 Mini-PRD。

本命令只定义“做什么、为什么做、做到什么程度”。不编码，不提交，不推送，不合并。

## 输入

用户的需求描述；可选提供相关 issue、原型、已有文档或功能名称。

## Step 0：加载共享协议与权威入口

读取：

1. `doc/ai/vibe-workflow-contract.md`；
2. 当前目录适用的 `AGENTS.md` / rules；
3. `doc/specs/baseline.yaml`；
4. `baseline.yaml` 指向的项目不变量和权威 PRD。

验证所有权威路径存在。若缺失或冲突，输出 `BLOCKED`，不要根据版本号或文件名猜测。

## Step 1：复述需求并识别决策状态

用简洁语言记录：

- 用户要解决的问题；
- 当前行为；
- 目标行为；
- 已明确的范围和限制；
- 模型做出的合理假设；
- 仍需产品决策的问题。

仅当缺失信息会改变产品范围、数据语义、权限、安全或不可逆设计时，才向用户提问。普通实现细节由后续设计阶段决定。

## Step 2：任务分类与风险分级

按共享协议标记影响域，并确定 `R0 / R1 / R2 / R3`。

以下情况至少为 R3：

- Schema 或 migration；
- FSM、并发唯一性或安全红线；
- 权限模型；
- 数据修复、历史兼容或不可逆操作；
- 核心结果计算和审计语义。

输出分级理由，不按文件数量判断风险。

## Step 3：渐进式读取项目上下文

先读取索引，再根据影响域读取最少但充分的上下文：

- 相关现有功能代码；
- 领域类型和状态机；
- Schema、迁移和 repository；
- IPC/API contract；
- 相关测试和已知缺陷；
- 适用的数据合同、权限矩阵和结果规则。

记录已读取的权威来源和适用的不变量 ID。

不得仅凭主 PRD 的摘要或历史任务书推断当前实现。

## Step 4：建立影响矩阵

生成并填写：

| 影响域 | YES/NO | 证据与说明 |
|---|---|---|
| UI / UX | | |
| Domain model | | |
| Database / migration | | |
| Event / projection | | |
| IPC / API | | |
| Authentication / authorization | | |
| Safety / FSM / concurrency | | |
| Result / report | | |
| Accessibility | | |
| Privacy / audit | | |
| Backward compatibility | | |
| Deployment / rollback | | |

允许填写 `NO`，不要为简单功能强行制造影响。

## Step 5：编写 Mini-PRD

保存到：

```text
doc/features/<feature-name>-prd.md
```

使用以下结构：

```markdown
# <功能名称> Mini-PRD

## 1. 文档状态
- 状态：DRAFT / REVIEWED / APPROVED / BLOCKED
- 风险等级：R0 / R1 / R2 / R3
- 权威依据：文件路径、章节或不变量 ID

## 2. 问题与目标
- 当前行为
- 用户问题
- 目标行为
- 成功定义

## 3. 用户角色与权限

## 4. 核心场景
使用 Given / When / Then 描述主路径。

## 5. 范围
### 本次包含
### 明确不包含

## 6. 行为与数据变化
- 状态变化
- 数据读写
- 事件/投影
- IPC/API
- 权限检查

## 7. 边界条件与异常处理
- 空数据
- 重复操作
- 并发
- 终态操作
- 中途失败
- 断线/重试
- 安全事件

## 8. 迁移与兼容性

## 9. 非功能要求
- 性能
- 可访问性
- 隐私与审计
- 可观测性

## 10. 验收标准
每条标准必须可由测试、命令或人工步骤验证。

## 11. 适用不变量
列出稳定 ID。

## 12. 风险、回滚与停止条件

## 13. 已确认决策、假设与未解决问题
```

## Step 6：独立 Reviewer 审查

调用 `/vibe-review prd <prd-path>`，并显式传入：

- Mini-PRD 全文；
- 风险等级；
- 权威资料路径；
- 适用不变量 ID；
- 本次特定安全、权限和结果规则。

不得假设 Reviewer 自动拥有主循环上下文。

最多进行两轮自动修订：

- P0 必须清零；
- P1 必须修复或记录为明确接受的残余风险；
- P2 不阻断，可进入 backlog；
- 两轮后仍有 P0，文档状态改为 `BLOCKED`，不进入实现计划。

R3 任务应由独立 Reviewer 审查；无法独立审查时，标记“非独立自审”，不得声称完全批准。

## Step 7：输出

输出：

- PRD 路径；
- 风险等级；
- 主要影响域；
- 适用不变量 ID；
- Reviewer 结论；
- 尚未解决的问题；
- 是否具备运行 `/vibe-impl` 的条件。

不得自动开始编码。
