# 会话结束：最小可恢复交接（SVETS 项目专用）

目标：让下一会话最低成本恢复现场。精简 > 完整，可恢复 > 可读。

---

## 步骤一：更新 `.continue-here.md`（全量覆写）

```md
# Current State
- 任务：<精确一句话，例如"实现 auth:login IPC handler">
- 当前 Vibe Coding 步骤：</vibe-feature | /vibe-impl | 逐步实现第N步 | /vibe-accept>
- 已完成：<具体到文件路径 + 验证结果，例如"src/main/ipc/handlers/auth.ts — typecheck 通过">
- 产出物：<文件路径或 commit hash>

# Next Action
- <下一步唯一原子动作，必须小到新会话开头可以立刻执行>

# Blockers
- <真实阻塞；没有则 None>

# Key Decisions
- <最多 3 条，只保留影响后续实现的决策>

# Relevant Files
- <下一步真正会打开的最小文件集>
```

规则：
- `Next Action` 必须是原子操作，不能写"完成 auth 模块"这种阶段目标
- `Relevant Files` 只列下一步真的会打开的文件，不要列背景材料
- Vibe Coding 步骤必须填，便于下次会话快速定位流程位置

## 步骤二：Vibe Coding 状态检查

根据当前所处步骤，决定是否有遗留事项：

| 步骤 | 检查项 |
|---|---|
| `/vibe-feature` 进行中 | Mini-PRD 是否已存入 `doc/features/`？ |
| `/vibe-impl` 进行中 | 实现文档是否已存入 `doc/features/`？ |
| 逐步实现中 | 当前步骤是否已完成？typecheck 是否通过？ |
| 待 `/vibe-accept` | 所有步骤是否已完成？是否已运行验收清单？ |

如有未完成事项，在 `.continue-here.md` 的 `Blockers` 中说明。

如本轮新增、移动、重命名或归档了 `doc/` 下的文档，执行：

```bash
npm run docs:index:update
npm run docs:index:check
```

`doc/index.md` 的自动清单区块不得手工编辑；任务导航、权威基线和阅读顺序仍需人工复核。

## 步骤三：Git 处理

先执行：
```bash
git status --short --branch
npm run typecheck 2>&1 | tail -5
```

分类处理：

| 情况 | 操作 |
|---|---|
| 本轮任务完整、typecheck 通过、已验证 | 精确 commit（功能改动提功能分支，docs/handoff/chore 可直接提 main）|
| 本轮任务未完成 | 不提交、不 stash，通过 `.continue-here.md` 交接 |
| 无关改动 | 跳过，说明原因 |

规则：
- 禁止 `git add .`，只允许精确 `git add <file>`
- 只有 `npm run typecheck` 通过才允许 commit
- 单人开发，不走 PR（详见 AGENTS.md「Git 规范」+「开发流程 Step 4」）：
  - 功能改动：在功能分支（feat/xxx）上 commit + 逐步验收（`/vibe-accept` 全绿）→ 本地 squash merge main → push main 备份
  - docs / handoff / chore 等非功能改动：可直接 commit 到 main
- `push` 失败时保留本地 commit，停止，不重试

提交信息格式：
```
type(scope): 简述本次变更

- Done: <核心完成项>
- Next: <下一步动作>
- Risk: <有则填，无则省略>

Co-Authored-By: Claude Opus 4.6 <noreply@anthropic.com>
```

## 步骤四：覆写 `doc/会话启动.md` 的 HANDOFF 区块

用 Edit 工具直接覆写 `doc/会话启动.md` 中的 HANDOFF 区块，内容取自当前 `.continue-here.md` 的 `Next Action` 和 `Relevant Files`。

定位方式：`old_string` 匹配整个 `<!-- HANDOFF:START -->` 到 `<!-- HANDOFF:END -->` 块（含两端注释行），`new_string` 替换为新内容，保留两端注释行。

模板：
```
<!-- HANDOFF:START -->
## 本次交接（自动生成，请勿手编）
- 当前任务：<精确一句话>
- 下一步唯一原子动作：<唯一原子动作>
- 验证命令：<做完后第一条验证命令>
<!-- HANDOFF:END -->
```

规则：
- `old_string` 必须包含完整的原 HANDOFF 区块（从 `<!-- HANDOFF:START -->` 到 `<!-- HANDOFF:END -->`），确保 Edit 精确定位
- 覆写后确认文件内容正确，不要额外追加
