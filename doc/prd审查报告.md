# 两份文档审查报告

先说结论：PRD 工程严谨度很高（安全红线、事件溯源、版本锁定都做得很好），但 **v1.0.5 的"口径重平衡"引入了几个你可能没意识到的结构性裂缝**，且优化建议报告里的多条建议与 PRD 的自动化评分体系**根本不兼容**。以下按严重程度排列。

---

## 一、最严重：两文档之间的隐性冲突

### 1. 优化报告的评分标准在线上自动判分下不可实现 ⚠️
优化报告中大量 1 分档定义为：
- "需改进(1分)：**经提示后选对**"
- "需改进(1分)：**犹豫后选A**"

这些标准依赖**评估人员现场观察学生的作答过程**。但 PRD 的线上 42 题是学生端自主答题、系统自动计分（`answer_record` 事件化写入）。系统无法判断"犹豫""经提示"。

**你必须二选一：**
- 线上题降为 0/2 二值计分（但这会破坏"每题 0/1/2、满分 100"的口径，42×2=84 分线上封顶不变，只是 1 分档消失）；
- 或者明确 MVP 测评是"教师陪测模式"，教师端有实时的 1 分标注入口——这是一个 PRD 里完全没有的功能。

这是两份文档最大的断裂点，会直接影响 schema 和交互设计。

### 2. 优化报告的"分挡"机制破坏标准化可比性
"2分钟档/3分钟档""轻型<3kg（女/体弱者）""低级平行替代题供评估人员灵活选用"——这些都是**个体化难度适配**。但 PRD 中：
- `normalized_score` 用于横向落档（80/60 阈值）和就业安置方向判定；
- 不同学生用不同档做题，得出的分数**不可比**，却被同一套阈值判定为"竞争性就业 vs 日间照料"。

要么在 `strategy_config` 中把"档位"做成显式策略版本（不同档 = 不同 strategy version，报告注明），要么禁止评估中临场换档。目前两份文档都没处理这个问题。

### 3. 感官过敏筛查（模块四新增 5 项）与 PRD 感官画像没有打通
优化报告建议嵌入测评的 1-5 分感官筛查，PRD 的感官画像是**教师手填的档案字段**。合理的设计应该是：筛查结果 → 回写/建议更新 `student_profile` 感官画像 → 影响后续组卷避让。目前缺少这条数据回流链路，筛查结果会变成死数据。

### 4. 新增/修订题目会打破 6×7=42 的组卷结构和历史可复现性
优化报告建议新增 8-12 题、修订约 8 题。但 PRD 有一个**你锁了策略版本却没锁题目版本**的漏洞：
- `strategy_config` 已引用版本不可改写——很好；
- 但 `question_bank` 里**已被历史 session 引用的题目**被"修订"（改题干、改评分 rubric、改素材）后，历史测评结果就不可复现了。

建议：题目也引入版本机制（或至少"已被 answer_record 引用的题目内容字段冻结，修订必须新建题目 ID 并将旧题 `ARCHIVED`"）。这应写进 §17.8 和第 19 章工程约束。

### 5. 难度体系对不上
PRD 难度映射只有 低/中/高 → 1/3/5，优化报告出现了"入门(预备级)""基础级""岗位关联中级""挑战档"等新标签，无法映射。需要扩展 `difficulty_level` 枚举或明确降维规则。

## 二、PRD v1.0.5 自身的不合理之处

### 6. 情绪崩溃"累计 3 次"的定义自相矛盾 ⚠️
§4.6 定义：崩溃 = "中断后**未恢复**（学生放弃或**教师终止当前测评**）"。但如果一次崩溃就意味着测评被终止，那**同一个 `assessment_session` 怎么可能累计到 3 次崩溃**？

隐含的真实意图大概是"终止当次、择日在同一 session 内续测"，但 PRD 的 session 状态机里没有"跨日挂起后继续"的明确路径（`SUSPENDED_REVIEW_REQUIRED` 语义未展开）。必须重写这段定义：明确崩溃后 session 进入什么状态、由谁恢复、恢复后从哪题继续、跨天是否算同一 session。否则开发时必然实现错。

### 7. 模块兜底存在"单题否决"和"除零"问题 ⚠️
线下 8 题按复合标签覆盖 6 维度，**不要求每维度 1 道**。那么：
- 某模块线下可能只有 1 题 → 该题得 0 或 1 分 → 线下模块得分率 0% 或 50% 边缘 → **一道题触发一票否决**，等级直接 NOT_COMPETENT。灵敏度过高，且违背测量学基本原则。
- 某模块线下可能是 **0 题** → 得分率 = 0/0，除零未定义。

建议：模块兜底只对**线上模块（每模块 7 题、14 分满分）**计算；线下 8 题的模块归属仅用于报告展示；或规定"模块题量 < N 时不参与否决"。

### 8. 线下 8 题与"拆箱上架实操评分"的关系没有厘清 ⚠️
v1.0.5 把测评改成了通用基础能力评估（含线下 8 道**通用**实操题：画圆、静坐、搬运等），但 §5.6 实操评分描述的仍然是"**拆箱与上架**"任务实操（9 个动作）。那么：
- `OPERATION_PASS_RATE` 来自哪一套线下评分？
- `offline_score_record` 是否同时承载"基础能力线下 8 题（喂 ABILITY_SCORE）"和"任务实操评分（喂 OPERATION_PASS_RATE）"？如果是，需要类型字段区分，且要防止一份数据被双重计入两类结果。

这是 v1.0.5 合并口径后遗留的最大模型裂缝，schema 层必须明确。

### 9. 测评中途终止（崩溃兜底/红线）时的分数计算规则缺失
只答了 20/50 题就触发兜底终止，`raw_score / max_score` 的 `max_score` 取 100 还是已答题满分？模块得分率对未答题怎么算？PRD 说"模块得分率 = 模块内**已答题目**实得分 / 模块内题目满分"，分母到底是已答还是全部？两处表述不一致（§7.4 细则用"已答题目实得分"但分母是"模块内题目满分"）。需要一条明确规则。

### 10. 单次测评直接输出"就业安置方向"的伦理与效度风险
"日间照料转介 / 支持性就业 / 竞争性就业"是影响人生走向的重大结论，却由**一次 50 题的测评**自动判定，且 MVP 只有一个任务样板做过验证。建议：
- 报告中标注为"**系统参考建议，须经专业评估团队复核**"；
- 支持"多次测评取趋势"而非单次定档；
- 80/60 阈值目前是拍脑袋值，应在 seed 数据上标注"待真实样本校准"。

另外 §7.4 建议结论第 6 条会让所有 `LEVEL_CONDITIONAL` 学生得到"回炉巩固训练"结论，与"支持性就业可上岗"的安置方向自相矛盾，文案要调和。

### 11. 文档内部版本自相矛盾
文档头部与 §0 宣称对齐 `schema v0.1.7`，§7.6 第 13 条说 v0.1.8 是"修订备忘（非本次范围）"，紧接着落地状态注释又说 "schema v0.1.8 **已执行全部修订**"。三处打架。工程基线必须唯一，否则开发按 v0.1.7 的 `pass_threshold` 字段名建表就错了。

### 12. 情绪崩溃兜底不覆盖 training_session
训练中反复崩溃没有任何累计机制或结论联动。如果是有意为之，应显式写"训练不设崩溃兜底"，否则算遗漏。

### 13. 50 题一次性施测对目标人群负荷过大
42 线上 + 8 线下，对认知障碍/注意缺陷学生可能需要 1-2 小时以上，测评疲劳本身会污染后半段模块得分（进而误触发模块兜底）。建议支持**分模块分段施测**（同一 session 多个坐次），并在报告记录各段施测时间——这也顺便解决第 6 条的跨天续测问题。

### 14. 管理员单点风险
所有阻断解除都依赖管理员，本地单机部署的学校可能只有一个管理员账号。管理员请假期间，一次误触红线（FALSE_TRIGGER）会让学生的测评训练卡死数天。可考虑"双教师联签临时解除 + 强制事后管理员复核"的降级通道。

### 15. 小问题
- §0 说题库来源是 `通用基础能力评估题库.xlsx`，§5.3.1 全程按 "CSV 字段" 描述映射，口径不统一。
- §17.8 第 12 条"`OFFLINE_OPERATION` 题目通过 ability_tags 参与**线上**模块计分"应为"线下模块计分"，文字错误。
- 每模块需 ≥7 道 `ACTIVE` 题才能组卷，而 `DRAFT→ACTIVE` 审核门槛很高（9 项前置条件）——需要一份明确的**题库审核冲刺计划**，否则 MVP 上线日测评根本发不起来。

## 三、可升级方向（优化报告中值得吸收进 PRD 的）

1. **规则×情绪交叉分析框架**（优化报告 §3.3）质量很高，建议进 PRD v1.1.0 的报告模块，作为"系统建议结论"的规则引擎升级——它比单模块兜底更有诊断价值。
2. **求助对象层级判断**（§5.2 的 5 场景表）可直接结构化为题目模板 + 报告中的"社交支持画像"。
3. **综合安全情景拖拽题**（多隐患标记）是很好的高区分度题型，但注意它的部分得分规则（找到 3/5 个隐患给几分）需要在 `scoring_rule_json` 中定义 rubric，目前 PRD 的 0/1/2 三档偏粗。
4. **安全模块作为基准校准模块**的思路可以制度化：在题库审核规则（§5.3.1）中加一条"新题需与模块六同类题对标评审"。
5. 感官筛查若纳入，建议做成**测评前置的独立轻量 session**（5-10 分钟），结果写入感官画像并影响组卷避让，而不是混进模块四计分——因为感官过敏严重度不应该扣"情绪调节"的分。

## 四、行动建议优先级

| 优先级 | 事项 |
|---|---|
| P0 | 解决 #1（线上 1 分档不可实现）、#6（崩溃累计定义矛盾）、#7（模块兜底除零/单题否决）、#8（两套线下评分关系）、#11（schema 版本打架） |
| P1 | #4 题目版本冻结、#9 中途终止计分规则、#10 就业安置复核声明、#2 分挡策略化 |
| P2 | #3 筛查回流、#12 训练崩溃、#13 分段施测、#14 管理员单点 |
| P3 | 吸收交叉分析框架等升级项进 v1.1.0 |

总体评价：PRD 的工程底座（事件溯源、安全红线生命周期、策略版本锁定）已经是超出 MVP 通常水准的严谨，但 v1.0.5 这次"评分口径重平衡"是产品规则层的大改，**它和底下这套严谨的数据模型之间的缝还没有缝合完**——上面 P0 的五条就是缝隙所在。建议出一版 v1.0.6 专门收口，再进编码。
