## 二、让 Schema 真正执行生命周期和验收条件

当前 Schema 虽然已经包含：

* `lifecycle_status`
* `production_method`
* `review_level`
* `gate_reviews`
* `source_path`
* `runtime_path`
* `file_hash`
* `overlay_spec`
* `rights`

但部分明显不合规的记录仍可能通过验证。

请在 `asset-manifest.schema.json` 中使用 Draft 2020-12 支持的 `allOf`、`if`、`then` 等条件约束，落实以下规则。

### 2.1 生命周期条件

#### `planned`

允许以下字段为 `null`：

* `generation_date`
* `source_path`
* `file_hash`

但必须已有：

* `asset_id`
* `asset_type`
* `usage_mode`
* `delivery_format`
* `production_method`
* `review_level`
* `lifecycle_status`
* `question_ids`
* `gate_reviews`
* `rights`

#### `generated`

必须有：

* 非空 `generation_date`
* 非空 `source_path`
* 非空 `file_hash`

AI生成资产还必须填写：

* `provider`
* `model`
* `prompt_template_id` 或 `prompt_text`
* 适用时填写 `route`
* 适用时填写 `size`
* 适用时填写 `resolution`

#### `composited`

必须有：

* 非空 `source_path`
* 非空 `file_hash`
* 非空 `overlay_spec` 或明确的合成规格
* `production_method` 必须是 `ai_plus_overlay`、`programmatic` 或 `composite` 之一

#### `reviewing`

必须有：

* 非空 `source_path`
* 非空 `file_hash`
* 完整 `gate_reviews`

#### `approved`

必须有：

* 非空 `source_path`
* 非空 `runtime_path`
* 非空 `file_hash`
* 非空 `rights`
* 所有 `required: true` 的验收门状态必须为 `passed`
* 不允许必需验收门仍为 `pending`、`rejected`、`revision_required` 或其他未通过状态

#### `retired`

允许保留历史文件和审核信息，但不得作为新的正式运行时资产使用。文档中说明其语义即可。

### 2.2 生产方式条件

#### `ai_direct`

AI生成资产应要求：

* `provider`
* `model`
* `prompt_template_id` 或 `prompt_text`

#### `ai_plus_overlay`

必须要求：

* 非空 `required_overlay`
* 非空 `overlay_spec`
* AI底片生成信息
* 程序叠加说明

#### `programmatic`

必须允许：

* `provider: "codegen"` 或 `"manual"`
* `model`、`route`、`quality` 等AI字段为 `null`

但必须填写能够追踪最终文件的路径和生产说明。

#### `composite`

必须要求：

* 非空 `reference_asset_ids`
* 非空 `overlay_spec`
* 合成所使用的组成资产或参考资产说明

### 2.3 审核级别条件

#### `standard`

最低要求：

* `technical.required = true`
* `visual.required = true`

若素材会直接呈现给特殊教育学生，则应根据资产类型或资产用途启用 `special_education` 验收。

#### `assessment_critical`

必须要求：

* `technical.required = true`
* `visual.required = true`
* `assessment.required = true`

职业岗位测评素材还应：

* `vocational.required = true`
* `special_education.required = true`

#### `safety_critical`

必须要求五道门全部为：

```json
"required": true
```

即：

* technical
* visual
* vocational
* special_education
* assessment

且在 `approved` 状态时五道门必须全部 `passed`。

### 2.4 Schema之外的跨记录校验

JSON Schema 无法可靠检查所有跨记录关系。请在规划书中增加说明：后续需由独立校验脚本检查：

* `asset_id` 是否全局唯一
* `reference_asset_ids` 是否真实存在
* `question_ids` 是否在题库中存在
* `expected_answer` 是否与题库一致
* `runtime_path` 是否全小写
* 文件是否真实存在
* `file_hash` 是否与文件一致
* 已批准资产是否完成全部必需验收门

本次如果不创建脚本，也必须把上述内容列为P0批量生产前的必做校验项。

## 三、修正中文文字规则，不再一刀切禁止AI生成中文

删除或改写规划书中以下过度严格的表述：

* “中文文字不由AI直接生成”
* “Do not render legible product names”
* 所有商品包装必须完全留空、不允许AI生成任何中文
* 已经正确生成的中文必须重新程序叠加

新的原则是：

> 允许GPT-Image-2生成普通中文品名、区域名称和包装短文字；根据文字对题目答案的影响程度，采用不同的生成和审核方式。

### 3.1 三级中文文字处理规则

#### A. 普通文字

可以由AI直接生成，完成一般人工目视检查后使用。

包括：

* 普通商品短品名
* 包装装饰性短文字
* 不参与评分的区域名称
* 背景场景标识
* 示范图中的普通步骤标题
* 不影响题目答案的环境文字

检查内容：

* 是否存在明显错字
* 是否清晰可读
* 是否出现随机乱码
* 是否出现未授权品牌或商标
* 是否出现与题目无关的额外文字

#### B. 识别关键文字

可以由AI生成，但必须逐字审核。

包括：

* “全脂牛奶”与“脱脂牛奶”
* “薯片”与“虾片”
* “鲜橙汁”与“橙味汽水”
* 商品类别名称
* 产地文字
* “临期专区”“问题商品区”等可能参与判断的标识
* 安全标志中的文字

检查内容：

* 每一个字必须正确
* 不得多字、少字、错字
* 同一商品不同版本的文字必须一致
* 字号、颜色、位置不得形成额外答案提示
* 不得只依靠颜色区分相似商品
* 文字必须在目标设备和应用尺寸下清晰可读

#### C. 数据关键文字

原则上由程序化方式生成，不依赖AI随机生成。

包括：

* 模拟工作日
* 生产日期
* 到期日期
* 剩余保质期天数
* 商品价格
* 数量
* 库存数字
* 送货单数据
* 计算结果
* 系统界面中的评分数据
* 条形码
* 二维码

其中：

* 日期、价格、数量等由SVG、Canvas、前端组件或视频后期准确叠加
* 条形码、二维码必须由程序生成
* 不接受“看起来像条形码但无法扫码”的AI结果
* 任何会直接改变题目正确答案的数据都必须做到确定、可复现

### 3.2 调整统一Prompt

不要再统一写：

```text
Do not render legible product names.
```

改为根据素材需求使用变量化规则。

允许AI生成中文品名时，可以使用类似：

```text
Render the following short Simplified Chinese product name exactly as written: “纯牛奶”.
The Chinese text must be clear, correctly spelled, and placed in the main label area.
Do not add any extra words, random characters, brand names, trademarks, dates, prices, barcodes, or QR codes.
```

需要后期叠加关键数据时，可以使用：

```text
Render the product name “纯牛奶” clearly and correctly.
Reserve a clean, unobstructed area for programmatic production-date and barcode overlays.
Do not generate dates, prices, quantities, barcodes, QR codes, or other numeric data.
```

场景图可以允许普通区域标识，但应禁止随机品牌和无关乱码。

### 3.3 Manifest增加文字处理字段

在 Schema 和 Manifest 中增加：

```json
"text_handling": "none | ai_reviewed | programmatic | mixed"
```

含义：

* `none`：素材中没有需要管理的文字
* `ai_reviewed`：文字由AI生成，并经过人工逐字或目视审核
* `programmatic`：所有关键文字均由程序生成
* `mixed`：普通品名由AI生成，日期、价格、条形码等由程序叠加

可以根据需要再增加：

```json
"ai_text_requirements": [],
"programmatic_text_requirements": []
```

或放入 `overlay_spec`，但不要重复设计过多字段。

商品“纯牛奶”的典型设置应为：

```json
"text_handling": "mixed"
```

含义是：

* “纯牛奶”可以由AI生成并审核
* 生产日期、到期日和条形码由程序生成

### 3.4 保持同一商品文字一致

同一商品的：

* 正常版
* 破损版
* 临期版
* 过期版
* 训练版
* 测评版
* 后续泛化版

应尽量基于同一批准母版编辑，保持：

* 商品名称
* 字体风格
* 标签位置
* 包装结构
* 主色关系
* 机位和比例

不得每次从零生成，导致同一商品在不同题中看起来像不同SKU。

## 四、修复过期商品图直接泄露答案的问题

当前异常商品设计中存在类似：

* 直接显示“已过期”
* 日历图标打叉
* 贴橙色“已过期”提示

这类画面可以用于教学讲解，但不能直接作为正式测评图，因为学生无需理解日期，只要识别提示词或叉号即可答题。

请按使用模式拆分。

### 4.1 训练和教学素材

可以在学生完成判断后显示：

* “已过期”
* 日历打叉
* 日期高亮
* 教师讲解提示
* 结果解释

但不得在学生作答前直接泄露答案，除非该素材明确属于示范教学。

### 4.2 正式测评素材

只能呈现客观信息，例如：

* 生产日期
* 到期日期
* 模拟工作日
* 商品本身的包装状态

不得出现：

* “已过期”
* “临期”
* “错误”
* 红叉
* 绿勾
* 指向答案的箭头
* 特殊高亮
* 只有错误项使用的醒目颜色

学生必须依据日期和门店规则完成判断。

### 4.3 同一素材建立不同版本

建议使用同一商品母版生成：

* `training` 版本
* `assessment` 版本

不要为了教学和测评分别从零生成不同包装。

例如：

* 训练解释版可以在作答后叠加“已过期”
* 正式测评版只显示准确日期

在 Manifest 中通过：

* `usage_mode`
* `question_ids`
* `text_handling`
* `required_overlay`
* `forbidden_visual_cues`
* `review_level`

明确区分。

### 4.4 异常难度命名避免与复杂度L0–L3冲突

当前整体素材复杂度已经使用：

* L0
* L1
* L2
* L3

临损商品的“明显损伤、中等损伤、细微损伤”不要再使用L1/L2/L3命名。

建议改为：

* `D1`：明显异常
* `D2`：中等异常
* `D3`：细微异常

或使用：

* `obvious`
* `moderate`
* `subtle`

同步修改规划书相关标题和说明，避免后续录入Manifest时混淆。
