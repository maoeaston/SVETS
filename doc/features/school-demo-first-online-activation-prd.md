## 2. 问题与目标

### 当前行为

1. 当前产品合同把 `PREVIEW_ONLY` 设计为独立发布、principal、签名批准、readiness registry 和 projection 链。
2. 新鲜安装中的 preview registry 默认保持 `INSTALLING`，学校无法直接体验 JOB_SKILL 预览业务。
3. 当前仓库没有在线激活模块，也没有可修改激活服务器地址的产品入口。
4. 教师、学生、测评、训练、评分和报告页面已存在，但没有一条以“学校演示可完整跑通”为首要目标的发布路径。
5. 新安装当前只加载 Schema 和开发账号，不会自动装入内容包声明的 96 道基础能力题和 298 道岗位题；教师端也没有 298 题只读目录路由。

### 用户问题

非业务安全机制已经成为学校看见产品价值的前置障碍。继续要求学校或项目方准备密钥、签名包和复杂安装信任链，会增加沟通与交付成本，并拖慢学校试用。

### 目标行为

1. 预览版与正式版使用同一套业务代码、路由、数据结构和操作流程。
2. 两者只通过应用版本号、发布说明和题库内容版本体现成熟度差异；正式版可在现有题库版本上继续扩容。
3. 软件使用权由一个简单的在线激活机制控制，激活服务器地址可以修改。
4. 学校获得演示授权后，可以从学生建档开始，完整体验测评、训练、教师评分和报告闭环。
5. 现有复杂 preview 信任链不再是学校演示或主业务流程的前置门；历史代码和数据先保留，后续单独决定是否删除。
6. 教师和专家可在同一软件的 `/teacher/question-bank` 路由浏览当前 298 道岗位题，不依赖 preview registry、principal 或签名发布链。
7. 新安装自动带入当前内容包；当前策略固定的 JOB_SKILL 18+6 题可跑完整演示，其余题目保持只读可见并按后续题库版本扩容。

### 成功定义

在一套显式隔离的安装环境中，配置激活服务器、输入有效授权码并激活后，教师能看到 298 道岗位题，教师和学生能够使用当前固定 18+6 题完成一条可重复的端到端业务闭环；无效、过期或超设备数授权不能进入业务页面。

## 3. 用户角色与权限

- 未激活用户：只能查看激活状态、修改激活服务器地址、提交授权码和重试验证。
- TEACHER：激活后按现有权限建档、发起测评/训练、评分和查看报告。
- STUDENT：激活后按现有权限完成自己的测评和训练。
- ADMIN：激活后管理账号和策略；激活服务器地址的修改不依赖已登录 ADMIN，以免未激活时无法配置，但必须由本机明确操作触发。
- 激活服务器：只判断授权码、安装实例、有效期和设备数量，不参与学生数据、题库内容、评分或报告计算。
- 学校名称属于授权展示信息，不是业务数据库的租户或数据权限来源；更换授权服务器或授权码不得自动迁移、清空或重新归属既有学生数据。

## 4. 核心场景

### 4.1 首次激活

Given 软件首次安装且未激活
When 用户填写可修改的激活服务器地址和授权码并点击激活
Then 主进程向服务器提交安装 ID、授权码和应用版本；服务器确认后保存本机激活状态并进入登录页。

### 4.2 学校演示

Given 软件已经使用学校演示授权激活
When 教师登录、建立学生档案并依次发起测评、训练和评分
Then 学生可完成自己的流程，教师可完成线下评分并查看最终报告。

### 4.3 题库查看

Given 软件已激活且教师或管理员已登录
When 打开教师题库目录并按模块、题型、状态或关键词筛选
Then 可查看当前 298 道 JOB_SKILL 题的题干、交互内容、实操材料和评分依据；该读取不要求 preview registry promotion，也不改变题目状态。

### 4.4 版本升级与题库扩容

Given 学校认可预览版本
When 发布新的正式应用版本或导入新的题库版本
Then 继续使用同一套业务流程和历史数据，不迁移到另一套“正式版系统”，也不要求重新建立 preview principal 或签名批准链。

### 4.5 授权失败

Given 授权码无效、过期或设备数已满
When 客户端激活或重新验证
Then 留在激活页面，显示明确原因，不进入业务页面，不修改学生或题库数据。

## 5. 范围

### 本次包含

1. 主进程在线激活客户端。
2. 可修改的激活服务器地址；部署环境变量可提供初始值，本机配置可覆盖。
3. 稳定的本机安装 ID；授权服务器按安装 ID 统计设备。
4. 激活状态查询、服务器配置、激活和重新验证 IPC。
5. 激活页面和全局路由守卫。
6. 一个仅用于开发和学校演示部署验证的最小激活服务器参考实现。
7. 教师端 `/teacher/question-bank` 只读题库目录，支持浏览 298 道岗位题及筛选、分页和详情展开；ADMIN 可读，STUDENT 禁止访问。
8. 新安装自动装入 `scripts/config/database-content-pack.json` 当前声明的 394 道题；已存在内容的数据库不得被启动流程清空或覆盖。
9. 当前 `strategy_job_skill_shelver_v1` 固定 18+6 题作为预览版本的完整业务演示集合；题目集合从策略数据读取，不在 UI 或授权模块重复硬编码。
10. 复用现有教师/学生/测评/训练/评分/报告页面，不新建平行 preview 业务流程。
11. 应用版本和题库版本在界面中可识别，但不改变业务算法。
12. 隔离 Electron 端到端演示脚本。

### 明确不包含

1. 支付、开票、订单、销售 CRM 或完整授权运营后台。
2. 自定义公钥/私钥、安装证书、bootstrap trust chain、principal enrollment 或签名批准作为软件激活前置条件。
3. 防破解、反调试、安装包防篡改或绝对防盗版承诺。
4. 删除现有 preview 表、事件或历史代码；删除需另行评估迁移和兼容风险。
5. 重新设计现有测评、训练、安全红线、评分和报告规则。
6. 访问、初始化、修改或 promotion 默认数据库。
7. 在本轮实现 BASE_ABILITY 尚缺失的 `SOFTWARE_TASK` 专用 renderer；该内容仍可在教师目录查看，但本轮完整演示使用当前 JOB_SKILL 固定 18+6 路径。

## 6. 行为与数据变化

### 激活客户端

- 主进程维护 `activation_server_url`、`installation_id`、`activation_token`、`license_status`、`organization_name`、`valid_until` 和 `last_verified_at`。
- renderer 不直接访问文件、数据库或网络授权接口，只通过 preload IPC 调用主进程。
- 授权码和 token 不写入日志、错误详情或 renderer 持久状态。
- 客户端使用标准 HTTP(S) 请求，不实现自定义签名协议。
- 所有配置、激活和重新验证操作在主进程内串行执行；重复点击同一激活请求不会产生并发本机写入。
- 业务 IPC 在进入现有 command/query 边界前等待当前激活操作结束并重新检查授权；已经通过检查并进入 durable executor 的命令允许按原合同完成，切换服务器不强行中断在途事件批次。

### 激活服务器最小合同

- `GET /health`：返回服务可用状态。
- `POST /v1/activations`：接收 `licenseKey`、`installationId`、`appVersion`，返回激活 token、学校名称、状态和有效期。
- `POST /v1/activations/validate`：接收 token、installation ID 和应用版本，返回当前状态。
- 状态至少包括 `ACTIVE`、`INVALID_LICENSE`、`EXPIRED`、`DEVICE_LIMIT` 和 `SERVER_UNAVAILABLE`。

### 本机持久化

- 激活配置和状态保存在应用 `userData` 下的主进程专用文件中，使用 atomic replace 和受限文件权限。
- 该文件不是业务事件源，不保存学生、题库、评分或报告内容。
- 默认数据库不参与本功能的配置或验收。

### 随安装内容包

- 新安装检测到对应题库域为空时，从随应用构建的当前内容包装入 96 道 `BASE_ABILITY` 和 298 道 `JOB_SPECIFIC` 题。
- 内容导入按题库域分别事务化；任一域失败时该域不得留下半包，另一域可在下次启动继续补齐。
- 已有题库数据时不得运行清库式同步。后续扩容继续通过显式版本内容包和兼容升级实现。
- 当前 JOB_SKILL 策略固定 18+6 题可进入同一正式业务代码路径；其余岗位题保持教师只读可见，不因软件激活自动获得学生作答资格。
- `BASE_ABILITY` 题不因软件激活自动绕过专业内容和 renderer 完成度；这不阻止 JOB_SKILL 演示闭环。

### 教师题库目录

- 目录直接读取 `question_bank` 当前内容，只做查询，不写题目、策略、事件或 preview projection。
- 主进程从 sender 绑定的有效登录会话解析角色，只允许 `TEACHER`、`ADMIN`；不信任 renderer 传入的 caller ID/role。
- 返回题目内容和评分依据，不返回学生作答、反馈正文、授权 token 或其他学校数据。
- 目录可展示 `DRAFT` 为“待评审”、`ACTIVE` 为“可演示”，但不得提供在页面内批量激活或改状态的按钮。

### 业务入口

- 未激活时只开放 runtime health 和 activation IPC。
- 激活后沿用现有登录、角色权限、事件批次和业务路由。
- 应用启动时在线验证；服务器暂时不可达时，只允许使用尚未超过服务器上次确认 `valid_until` 的缓存授权。
- 激活失效只阻止新的业务操作，不删除本地历史数据。
- 教师题库目录属于业务 IPC，同样必须先通过软件激活和登录角色检查。

### 预览与正式版本

- 不建立两套应用或两套业务路由。
- package version 和发布说明表达“预览/正式”状态。
- 题库扩容继续使用现有题目版本、策略版本和内容导入机制。
- 原 `PREVIEW_CONTRACT_V1` 可继续保留为历史兼容/实验能力，但不得阻止主业务演示，也不得作为软件激活条件。

## 7. 边界条件与异常处理

- 服务器地址为空或不是合法 URL：本地校验失败，不发请求。
- 正式打包环境默认要求 HTTPS；开发/演示可显式使用 loopback HTTP。
- 网络超时：返回可重试错误；存在未过期缓存授权时继续使用，否则停留在激活页。
- 重复激活同一 installation ID：幂等返回当前激活。
- 同一授权码达到设备上限：返回 `DEVICE_LIMIT`，不覆盖现有设备。
- 修改服务器地址：立即清除旧服务器 token 的可用状态，要求在新服务器重新激活。
- 修改服务器地址与业务请求并发时，以业务请求是否已经通过主进程激活检查并进入 durable executor 为边界；已进入的命令完成，尚未进入的请求按新地址对应的未激活状态拒绝。
- 激活、重新验证和修改服务器地址串行执行；后发操作等待前一操作完成后再读取最新状态，不允许较早响应覆盖较新配置。
- 服务器返回非 JSON、缺字段、未知状态或 installation ID 不匹配时，按服务器异常处理，不得覆盖尚在有效期内的已确认缓存授权。
- 应用升级：保留 installation ID 和有效激活状态，并向服务器提交新 app version。
- 激活文件损坏：失败关闭到激活页，不影响业务数据库完整性。

## 8. 迁移与兼容性

- 第一阶段不新增业务 Schema/migration；激活状态使用独立 `userData` 配置文件。
- 新安装只在对应题库域为空时装入随安装内容包；每个题库域单独事务提交，失败可重试。
- 已存在题目时，启动流程不执行清空、覆盖或全量重灌；后续内容扩容继续走显式版本升级。
- 现有 preview schema、projection 和测试保留，避免在 dirty 工作树中进行破坏性回退。
- 当前权威 PRD 中要求独立 preview 签名/发布链的章节与本决策冲突，标记 `[!]`；实施前同步权威 PRD、baseline 和交接文档，明确该链不再是学校演示前置条件。
- 既有正式测评、训练、结果和报告历史不发生语义迁移。

## 9. 非功能要求

- 激活请求默认超时不超过 8 秒，并显示可重试状态。
- activation token、授权码不得出现在日志、错误事件或报告导出中。
- 激活服务器 URL 修改必须有明确确认，避免误切换导致授权失效。
- 激活页面支持键盘操作、明确焦点、可读错误和窄屏布局。
- 参考服务器不新增 ORM、付费服务或第三方授权 SDK。

## 10. 验收标准

- `AC-01`：可在未激活状态修改服务器地址，并在重启后保持。
- `AC-02`：有效授权码激活后进入登录页；无效、过期和设备超限显示稳定错误。
- `AC-03`：服务器地址修改后旧 token 不再放行业务入口。
- `AC-04`：renderer 无法直接读取 activation token 或绕过 preload 发起业务 IPC。
- `AC-05`：激活后教师可建档并发起既有业务流程；未激活时业务 IPC 失败关闭。
- `AC-06`：使用当前 JOB_SKILL 固定 18+6 题，学生可完成测评/训练，教师可评分并查看报告；该流程不依赖 `PREVIEW_CONTRACT_V1` registry promotion。
- `AC-07`：应用升级后 installation ID 和有效授权保留，题库可通过新版本继续扩容。
- `AC-08`：默认数据库未访问；全部验收使用显式隔离 `userData` 和数据库。
- `AC-09`：typecheck、lint、相关测试、build、Electron 端到端演示通过。
- `AC-10`：版本界面能看见应用版本与题库版本，但不存在平行“预览系统/正式系统”入口。
- `AC-11`：显式隔离的新安装首次启动后包含 96 道 BASE_ABILITY 和 298 道 JOB_SPECIFIC；重启不会覆盖已有题目或用户修改。
- `AC-12`：已激活的 TEACHER/ADMIN 可分页筛选并查看 298 道岗位题；STUDENT、未登录或未激活调用均被拒绝。
- `AC-13`：`preview_contract_registry` 保持 `INSTALLING` 时，题库目录和 JOB_SKILL 18+6 演示仍可使用，且不会写入 preview principal、release 或 feedback 数据。
- `AC-14`：并发修改服务器、激活、重新验证和业务请求的故障注入测试证明：旧响应不会覆盖新配置，已进入 durable executor 的命令不会留下半批事件。

## 12. 风险、回滚与停止条件

### 风险

- 激活服务器不可用会影响新安装和重新验证。
- 只做普通在线激活不能承诺绝对防破解；本项目目标是控制正常授权安装，不是对抗专业逆向。
- 服务器地址可修改意味着兼容本合同的自建服务器可以绕过授权；这是用户为降低学校试用成本而明确接受的剩余风险，本轮不再用自定义签名或固定信任锚消除它。
- 固定 18+6 只用于展示当前闭环和既有计分路径，不等于学校已经验收全部 298 题，也不能生成或暗示就业安置建议。
- 当前权威 PRD 与新产品决策存在冲突，必须显式更新，不能同时维护两套互斥口径。

### 回滚

- 停止 activation IPC 和路由守卫，恢复当前直接登录行为。
- 保留 activation 配置文件供诊断，不删除业务数据库或历史数据。
- 不回滚或删除现有 preview schema/event/projection。

### 停止条件

- 激活功能要求访问默认数据库才能验证。
- 激活 token、授权码或学生数据进入日志/报告。
- 为防复制再次引入自定义签名、principal 或安装信任链作为演示前置条件。
- 激活 gate 改变现有安全红线、评分或报告语义。
- 无法在隔离 Electron 环境跑通学校演示闭环。
- 教师目录无法稳定显示当前 298 道岗位题，或仍依赖 preview registry、principal、签名发布链才能读取。

## 13. 已确认决策、假设与未解决问题

### 已确认决策

1. 在线激活可接受。
2. 激活服务器地址必须支持修改。
3. 预览版与正式版是同一套软件，差异主要是版本号、认可状态和题库规模。
4. 学校演示和业务闭环速度优先于非业务安全增强。
5. 不再假设有人伪造或篡改安装包作为当前产品前提。
6. 教师和专家需在同一应用内浏览 298 道岗位题；当前 JOB_SKILL 固定 18+6 负责跑通端到端演示。

### 合理假设

- 学校演示现场具备短时联网条件。
- 第一阶段只需要少量授权码和设备数管理，可由最小参考服务器满足。
- 现有角色、业务权限、安全红线和结果体系保持不变。

### 未解决问题

- 正式激活服务器的域名、部署账号和运维责任不在当前仓库中；客户端和参考服务器先使用可配置地址完成验证。
- 正式授权套餐、价格、设备数和续费规则由后续商务配置决定，不阻断学校演示。
- 独立 R3 代码审查待 Reviewer 服务恢复后补做；当前实现按用户批准的产品方向和非独立技术复核推进，不宣称独立 `PASS`。
