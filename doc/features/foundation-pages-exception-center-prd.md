# F5 基础页面与异常中心 Mini-PRD

- 状态：`APPROVED_FOR_IMPLEMENTATION`
- 产品合同：`doc/specs/MVP_PRD_v1.0.9-authoritative.md`
- 计划来源：`doc/features/pilot-r0-foundation-development-plan-2026-07-22.md` F5
- 日期：2026-07-23

## 1. 目标

让教师、学生、管理员登录后先看到与本人职责一致的工作入口和当前状态；让教师与管理员可以从异常列表进入详情，看到阻断级别、关联对象、恢复提示和恢复状态。学生不得接触异常技术信息。

本阶段只建立入口、反馈和只读事实查询。安全事件仍沿用 F4 的两级责任边界：教师补录并确认事实，管理员解除或作废阻断。

## 2. 最小闭环

```text
登录并恢复可信会话
  -> 角色首页显示待办和入口
  -> 进入业务列表或异常列表
  -> IPC 返回加载 / 空数据 / 无权限 / 阻断 / 可重试 / 成功之一
  -> 异常详情显示恢复提示与历史恢复状态
  -> 安全事件详情按角色开放合法动作
```

## 3. 角色范围

### 3.1 学生

- 首页仅显示通过 `student_profile.user_id` 关联到本人的测评与训练。
- 状态文案使用简短、温和、非技术表达。
- 不显示异常中心入口、错误码、堆栈、恢复日志或其他学生数据。

### 3.2 教师

- 首页展示学生、测评、训练、安全事件、报告五类入口及待处理数量。
- 可以查看教学相关异常，不查看纯系统维护异常的技术上下文或堆栈。
- 可以进入安全事件详情，对 `PENDING_DETAIL` 事件补录事实并推进到 `CONFIRMED`。
- 不得解除或作废安全阻断。

### 3.3 管理员

- 首页展示账号、策略、资源校验记录、安全解除、备份恢复状态和系统异常入口。
- 可以查看全部异常详情和技术上下文。
- 可以对合法状态的安全事件执行 `RESOLVED` 或 `VOIDED`；不得绕过状态机直接修改 session。

## 4. 页面状态合同

核心列表和详情使用同一组页面级状态：

| 状态 | 显示要求 | 下一步 |
|---|---|---|
| 加载 | 保持稳定占位，不显示空数据结论 | 等待完成 |
| 空数据 | 说明当前没有记录，不伪装成错误 | 返回首页或进入创建入口 |
| 无权限 | 说明当前账号不能查看，不泄露对象内容 | 返回角色首页 |
| 阻断 | 页面内持续显示，不只使用 Toast | 查看异常详情或联系责任角色 |
| 可重试错误 | 说明未加载成功，保留页面结构 | 原地重试 |
| 成功 | 使用 `role=status` 的稳定反馈 | 继续当前流程 |

## 5. 异常中心合同

- 列表关联 `error_event_log` 与 `error_code_registry`，展示 P0-P3、严重度、是否阻断、恢复状态、时间和关联对象。
- 默认查看最近 30 天，支持按优先级、类别和恢复状态筛选。
- 详情展示登记标题、实际消息、默认恢复提示、已执行恢复动作、关联对象和解决时间。
- 教师只能查看教学相关异常，并且不返回 `stack_trace` 与原始 `context_json`。
- 管理员可查看系统级异常和技术上下文。
- 学生从主进程被拒绝，不能依赖前端隐藏实现权限。
- 异常详情不提供通用“标记已解决”按钮；`recovery_status` 只能由真实恢复动作更新。

## 6. 安全事件入口合同

- 列表显示学生、任务、状态、发生时间、原因、环节和绑定会话数。
- 详情显示事实字段和历史状态，不允许原地覆盖已冻结事实。
- 教师只在 `PENDING_DETAIL` 状态看到“补录并确认”。
- 管理员在 `CONFIRMED` 状态可解决或按明确原因作废，在 `PENDING_DETAIL` 状态只可作废。
- 关键操作遵循 PRD §15.5 二次确认；安全红线触发本身仍不增加确认步骤。

## 7. 非范围

- 不实现 F6 评分计算。
- 不实现 F7 报告列表、详情、锁定或导出，只展示报告入口与现有快照数量。
- 不执行题库或资源激活，不生成激活 SQL。
- 不执行真实备份、恢复或资源文件 hash 重算；管理员入口仅展示已登记状态和异常记录。
- 不写真实运行数据库，测试使用内存库或临时库。
- 不提供异常日志删除、批量忽略或静默改写恢复状态。

## 8. 验收标准

1. 地址栏访问不属于本人角色的页面会被路由守卫送回角色首页；对应 IPC 仍独立拒绝越权。
2. 教师首页五类入口和数量可加载，加载失败可原地重试。
3. 学生首页同时展示本人测评与本人训练，不能读到他人任务。
4. 管理员首页能进入账号、策略、安全、异常、资源记录和恢复状态入口。
5. 异常列表覆盖 P0-P3，详情可查看恢复提示；P0/P1 阻断状态在页面内持续可见。
6. 教师看不到纯系统维护异常的技术上下文；学生不能调用异常 IPC；管理员可以查看完整详情。
7. 安全详情的教师与管理员动作严格符合 F4 状态机。
8. 1280×720、1366×768 和 375px 宽度下无文字遮挡、按钮溢出和状态切换跳动。
9. 类型检查、linter、相关测试、全量测试、构建、文档索引和差异检查通过。

## 9. 已知边界

- [!] `error_event_log` 当前同时承载异常与 INFO 级审计记录。F5 不改 schema，异常中心通过优先级、恢复状态和角色可见范围筛选，后续若要把业务审计与异常物理分表，需独立 schema 评审。
- [!] 运行时尚无执行资源 hash 校验或真实备份恢复的管理员 IPC。F5 只提供诚实的状态入口，不展示虚假的“校验通过”或“备份成功”。
