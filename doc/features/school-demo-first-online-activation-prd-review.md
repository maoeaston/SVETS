# 学校演示优先与在线激活 Mini-PRD R3 复核

## 1. 结论

- 结论：`CONDITIONAL_PASS_NON_INDEPENDENT`
- 审查等级：`R3`
- 对象：`doc/features/school-demo-first-online-activation-prd.md`
- 产品授权：用户已明确批准实施
- 独立性：未满足。两次独立 Reviewer 调用没有返回结果，第三次返回上游 `502 Bad Gateway`，因此本文件不得被引用为独立 R3 `PASS`。

该方案可以进入本地实现和学校小范围演示验证。正式对外发布前仍需补一次独立代码审查；这项审查债务不再被解释为学校演示必须等待的产品门禁。

## 2. 阻断项检查

| 检查项 | 结论 | 依据 |
|---|---|---|
| 默认数据库风险 | 通过 | 验收明确只使用显式隔离 `userData` 和数据库 |
| 业务安全语义 | 通过 | 不修改安全 FSM、结果分离、报告和 placement advice |
| 权限边界 | 通过 | 激活在主进程检查；题库目录使用 sender 绑定会话，只允许 TEACHER/ADMIN |
| 数据破坏风险 | 通过 | 内容包仅对空题库域装入，不清空或覆盖已有题目 |
| 并发一致性 | 通过 | 激活操作串行；在途业务命令以进入 durable executor 为边界 |
| 隐私和密钥泄露 | 通过 | 授权码不持久化，token 不进入 renderer、日志或报告 |
| 旧 preview 门禁耦合 | 通过 | 298 题目录和固定 18+6 演示明确不依赖 registry promotion、principal 或签名链 |

未发现 `P0`。本轮自审最初发现的三个 `P1` 已写回合同并关闭：教师 298 题路由缺失、新安装没有内容包、服务器切换与业务请求的并发边界不清。

## 3. 接受的剩余风险

1. 可修改激活服务器地址意味着兼容接口的自建服务器可以绕过普通授权。产品负责人已明确接受该取舍，本轮不通过自定义公私钥或固定信任锚解决。
2. 正式服务器域名、部署账号、授权套餐和运维负责人尚未确定。仓库内参考服务器足以验证客户端与学校小范围演示，不等同于生产授权平台。
3. 独立 Reviewer 服务不可用。实现完成后必须记录自动化与实机证据，并在正式发布前补独立代码复核。

## 4. 实施约束

- 先同步权威 PRD 和 `baseline.yaml`，再修改代码。
- 保留现有 preview schema 和历史代码，不做破坏性删除。
- 不启动或修改默认数据库。
- 新增业务 IPC 必须由主进程统一做激活和角色检查。
- 固定 18+6 题 ID 从策略数据读取，不在 UI 或激活模块重复硬编码。
