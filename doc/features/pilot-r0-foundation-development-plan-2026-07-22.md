## 1. 先说结论

计划可以先定稿、再分批落地，但不是所有缺口都能留到最后。

可以后置到题库准备阶段的内容：

- BASE_ABILITY 42+8 的正式题目组合、答案键、逐题评分规则、DRAG/SOFTWARE_TASK 资源和 8 道线下评分锚点。
- JOB_SKILL 的 R1-R6 核心参考资产、270 项素材生产审核和 Pilot 独立见证。
- 两条题库的受控激活、真实组卷和正式报告结论；其中 BASE_ABILITY 必须按方案 A 先经独立 Pilot 激活，再做课堂试测，试测证据通过后才讨论正式解释/发布。

不能后置的底座：

- 学生档案与账号的可靠关联。
- 主进程权限校验和角色边界。
- 每次操作写入成功或失败的明确结果。
- 暂停、恢复、安全红线的状态机和历史记录。
- 评分结果彼此隔离，不把不同分数混成一个总分。
- 报告快照不可被重测静默覆盖。

这些底座可以使用测试夹具和 DRAFT 数据验证，不需要为了开发它们提前激活题库。

## 3. 依赖顺序

```text
学生档案与账号
        |
        v
登录会话与权限 -----> 基础页面/异常提示
        |
        v
数据保存与事件恢复
        |
        v
暂停恢复 ---------> 安全红线
        |                |
        +--------+-------+
                 v
             评分计算
                 |
                 v
             报告快照

题库答案/素材合同 ---> Pilot 激活 ---> 课堂试测 ---> 正式解释/发布（分阶段开放）
```

题库补料不会阻塞左侧底座开发；它按阶段阻塞“提交 Pilot 激活、执行真实课堂试测、形成正式能力解释和发布”。BASE_ABILITY 的课堂证据不反向阻塞首次 Pilot 激活，但会继续阻塞正式解释与发布。

## 4. 分阶段实施

每个阶段都必须能单独合并、单独回归；后续阶段未完成时，前一阶段仍然有独立价值。

### F1 学生档案与账号一致性

实施状态：`COMPLETED_2026-07-22`。相关学生档案测试 61/61、全量测试 870/870 通过；临时全新数据库按当前内容包同步并校验通过。默认运行数据库只读校验发现既有内容包漂移，因本任务禁止写真实运行库而保留为独立运维事项。

范围：

- 创建学生时同时写入 `student_profile.user_id`。
- 学生详情和列表通过 `student_profile.user_id` 读取账号，不再依赖“两个主键刚好相同”的隐式关联；无账号档案仍可查看和归档。
- 姓名修改与绑定账号显示名在同一事务更新；任一字段校验或写入失败时不留下半套数据。
- 归档时通过已绑定的 `user_id` 停用对应学生账号；无账号档案仍可归档。
- 保留 `student_id` 与 `user_id` 当前同 UUID 的兼容做法，但不再把它当作查询前提。

验收：

- 新建档案后 `student_profile.user_id` 非空且指向 STUDENT 账号。
- 账号 ID 与档案 ID 不相同时，查询和归档仍操作正确账号。
- 归档只停用绑定的 STUDENT 账号，不影响其他账号。
- 学生档案现有创建、编辑、归档测试全部通过。

### F2 登录会话与权限收口

实施状态：`COMPLETE_2026-07-23`。已完成 PASSWORD `auth_session` 登录/刷新恢复/退出，会话身份已收口到 `student / strategy / assessment / training / assignment` 的 IPC 包装层；管理员账号维护已提供不泄露密码或令牌的 `auth:listAccounts`、仅创建 ACTIVE TEACHER 的 `auth:createTeacherAccount`，以及会立即撤销有效会话的 `auth:setTeacherAccountStatus`。系统级角色矩阵、全量测试、类型检查、构建和文档索引检查均已通过。

范围：

- `auth:login` 成功后建立 PASSWORD `auth_session`，渲染进程只保存会话凭证和展示信息。
- 主进程从会话凭证解析真实用户和角色；管理型 IPC 不再相信渲染进程单独传入的 `callerRole`。
- 管理员提供教师账号创建、停用和重新启用入口；教师只能维护学生档案，学生只能访问自己的分配与会话。
- 路由元数据声明允许角色，前端守卫只负责页面体验，主进程继续承担最终权限判定。

验收：

- 伪造 `callerUserId/callerRole` 不能越权。
- 过期、撤销、停用账号的会话全部被拒绝。
- STUDENT 不能读取他人 session；TEACHER 不能进入 ADMIN 维护 IPC；ADMIN 不能绕过安全事件状态机。
- 登录、退出、应用刷新后的会话恢复和撤销都有测试。

### F3 数据保存与恢复闭环

范围：

- 对答题、训练步骤、评分、红线和报告写入统一返回“已持久化”确认。
- JSONL 成功但 SQLite 投影中断时，启动恢复器按事件序列补投影；损坏尾行按 PRD 截断并记录恢复事件。
- SQLite 写入失败、JSONL 失败、checksum 不一致进入异常中心并阻断后续业务动作。
- 不引入前端持久化库；页面状态始终从主进程 IPC 重新读取。

验收：

- 强退后恢复到最后一条已确认记录之后，已提交答案不丢。
- 重放前后投影一致，重复重放幂等。
- P0/P1 保存故障不会显示虚假的“提交成功”。
- 运行 `npm run db:verify` 和恢复专项测试。

### F4 暂停恢复与安全红线

范围：

- 分开“情绪中断后当次恢复”“教师计划暂停到下一坐次”“因崩溃结束坐次”“安全红线熔断”四种语义。
- 教师可暂停/恢复/作废测评；学生恢复后进入下一道未提交题。
- 教师可一键触发红线、随后补录并确认；管理员可按合法状态机 RESOLVED/VOIDED。
- 未解决安全事件阻断同一学生同一任务的新测评和训练；红线优先级高于普通暂停。

验收：

- 覆盖 PRD §17.4 和 §17.5 全部场景。
- 同时开放的测评和训练被一次红线全部熔断，原有记录不删除。
- 教师和管理员越权状态迁移被主进程及数据库双重拒绝。
- Electron 中完成一次暂停恢复和一次安全事件两级处理见证。

### F5 基础页面与异常中心

范围：

- 教师首页展示学生、测评、训练、安全事件、报告五类工作入口及待处理数量。
- 学生首页只展示本人已分配任务及明确状态。
- 管理员入口展示账号、策略、资源校验、安全解除和备份恢复。
- 所有核心页具有加载、空数据、无权限、阻断、可重试和成功反馈状态。
- 新增 P0-P3 异常列表与详情页，展示恢复提示，不允许只用 Toast 处理阻断异常。

验收：

- 三种角色无法通过地址栏进入不属于自己的页面。
- 每个核心页面在空数据和 IPC 失败时均有稳定布局和明确下一步。
- 桌面和常用小屏窗口无文字遮挡、按钮溢出和状态跳动。

### Q1 BASE_ABILITY 正式施测补料

在 F1-F7 可使用测试夹具推进的同时，按以下顺序补齐：

1. 锁定 42 道线上 + 8 道线下 DRAFT 施测组合。
2. 补线上答案键、`scoring_rule_json` 和评分器夹具。
3. 补 DRAG/SOFTWARE_TASK renderer、资源和无障碍交互。
4. 补 8 道线下题标准教具、布置/复位说明与 0/1/2 行为锚点。
5. 完成内容/测评、安全/康复、特教/无障碍审核，以及合成身份显式临时库技术演练；只生成 `READY_FOR_PILOT_ACTIVATION_REVIEW` 证据，不自动激活。
6. 由产品负责人书面指定、且独立于内容制作、代码实现、门禁生成和激活执行的批准人签发 `PILOT_ONLY` 激活批准；`ADMIN` 只能按批准文件将所选 50 题转为 ACTIVE，其余 46 题继续 DRAFT。
7. Pilot ACTIVE 后，完成学校协议、适用知情同意、数据保护和完整多设备授权链，再执行真实课堂试测。
8. 课堂证据经接受后，另行评审阈值、模块权重、报告用语和正式发布；任何语义变化通过新题目/新策略版本实现，不改写历史 Pilot。

## 5. 明确不做

- 本计划不批量把 96 道 BASE_ABILITY 或 298 道 JOB_SKILL 题改为 ACTIVE；只允许方案 A 下获独立批准的 BASE_ABILITY 选定 50 题进入受控 Pilot ACTIVE。
- 计划和实现步骤本身不预授激活权限；激活工具必须拒绝缺失、过期或 hash 不匹配的批准文件，不得写未明确指定的运行数据库，也不得绕过机器门禁。
- 不实现 298 题随机组卷、PDF 报告渲染、家长端、企业端或 AI 最终录用/淘汰裁决。
- 不在本轮引入 ORM、前端持久化库、CSV 解析库或 Markdown 报告渲染库。

## 6. 风险与回退

- 最脆弱假设：现有 handler 和 reducer 的业务语义大体正确，主要问题是跨模块接线和验收缺口。如果 F3/F4 发现事件顺序与 schema 触发器冲突，暂停页面扩展，先修复事件合同和重放一致性。
- 每阶段只做可回滚的代码和文档变更；schema 变化必须带 migration、备份和回滚验证。
- 所有测试使用内存库或临时库；没有明确授权时不得写 `xc-career-guide.db`。
- 题库素材迟延不会迫使底座回滚，只会继续阻止提交 Pilot 激活；Pilot 激活后的课堂证据缺口继续阻止正式解释与发布，不要求把已批准且无缺陷的题退回 DRAFT。
