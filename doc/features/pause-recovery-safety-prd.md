# 暂停恢复与安全红线两级处理

对应主 PRD：`doc/specs/MVP_PRD_v1.0.9-authoritative.md` §3.4、§4.4 至 §4.6、§17.2  
状态：`IMPLEMENTED_VERIFIED_2026-07-23`

## 目标

把学生暂时不能继续、教师按计划暂停和安全红线处理分成不同的可追溯路径。每次连续施测都有独立坐次记录，安全事件先由教师补录确认，再由管理员作出最终处理。

## 业务规则

1. 学生情绪中断后，学生本人或教师可以恢复，恢复时保留当前未提交题，不跳题、不重置答案。
2. 教师可按计划结束当前坐次。测评进入“待复核”，不会被作废；教师开始下一坐次后，学生从当前未提交题继续。
3. 每个坐次都记录开始人、开始时间、结束人、结束时间、结束原因和当时题号。同一测评最多只有一个未结束坐次。
4. 教师确认学生无法在当次坐次恢复时，坐次以 `ENDED_BY_COLLAPSE` 结束，session 进入“待复核”。累计崩溃坐次达到策略阈值时，session 才完成，并强制为“不胜任”。
5. 红线触发立即阻断关联测评和训练，不等待详情补录。初始安全事件为 `PENDING_DETAIL`。
6. 教师只能补充事实并将事件确认到 `CONFIRMED`。管理员只能将已确认事件解除为 `RESOLVED`，或按允许的非事实原因作废为 `VOIDED`。
7. 如原始事实需要更正，管理员必须创建替代安全事件并保留原事件与替代事件之间的审计关联，不得直接覆盖历史事实。
8. `PENDING_DETAIL` 和 `CONFIRMED` 事件持续阻止该学生的新测评和训练。`RESOLVED`、`VOIDED` 属于终态，可解除这一阻断。

## 不在范围

- 不修改题库激活、评分阈值或正式施测门禁。
- 不删除既有测评、坐次或安全事件。
- 不写入真实运行数据库，验证只使用内存库和临时测试数据。

## 验收

1. 旧的进行中测评第一次继续时会补建首个坐次，之后可按计划暂停并开始下一坐次。
2. 学生不能恢复他人测评，教师不能执行管理员的安全终态操作。
3. 安全事件只允许 `PENDING_DETAIL → CONFIRMED → RESOLVED`，或在允许条件下进入 `VOIDED`。
4. 每一步都写领域事件，冷启动恢复可以重建坐次和安全事件状态。
5. 类型检查、相关单元测试、全量测试、构建、文档索引检查和差异检查全部通过。
