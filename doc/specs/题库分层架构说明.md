# 题库分层架构说明

**文档版本：** v0.1（草稿）  
**关联 schema 版本：** v0.1.10-scoring-closure（现行）→ v0.2.0-question-role（待落地）  
**关联 PRD：** v1.0.6  
**最后更新：** 2026-07-05

---

## 1. 背景与动机

当前 `question_bank` 表中有两类题目：

| 前缀 | 数量 | 来源 | 用途 |
|------|------|------|------|
| `Q_BASE_*` | 253题 | 通用基础能力评估题库.xlsx | MVP 基础能力测评（岗前简测） |
| `M1_*–M6_*` | 298题 | data/questions-m1.csv … m6.csv | 专业岗位技能（超市理货员） |

298道 M1–M6 题是按岗位构念精心设计的"核心题"，具备三项价值：  
1. 定义各岗位构念与标准作业规则  
2. 作为正式阶段测评/结业测评的候选题  
3. 作为后续训练变式题的质量基准（母题）

**问题：** 当前 schema 没有区分"哪些题用于测评、哪些用于训练、哪些用于结业"。若直接把训练题混入题库，会导致：  
- 训练中反复出现的题，在结业考试中原样出现，结业分数反映记忆而非独立掌握  
- 母题被随意修改，失去版本一致性和构念基准地位  
- 组卷策略无法精准控制题目用途

**目标：** 在 `question_bank` 表新增两个字段（`question_role` 和 `parent_question_id`），配合 `strategy_config.question_policy_json` 中的 `allowed_roles` 参数，实现用途隔离。

## 2. 四层题库定义

### 2.1 层级总览

```
┌─────────────────────────────────────────────────────────────┐
│  MASTER 母题库（298题 M1–M6，冻结保护）                      │
│  → 定义构念与标准规则；正式阶段测评候选；变式质量基准         │
├─────────────────────────────────────────────────────────────┤
│  TRAINING_VARIANT 训练变式题库                               │
│  → 与母题同构念不同表面；训练时使用；指向 parent_question_id │
├─────────────────────────────────────────────────────────────┤
│  GENERALIZATION 泛化训练题库                                 │
│  → 新情境/跨岗位迁移练习；也指向 parent_question_id         │
├─────────────────────────────────────────────────────────────┤
│  GRADUATION 结业候选池                                       │
│  → 与母题构念一致但表面已替换；按学员曝光记录动态排除后抽取  │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 各层定义与边界

#### MASTER — 核心测评母题

**定义：** 由专业人员审定的、明确定义一个岗位构念与标准作业规则的题目。

**入层判断标准（全部满足）：**
- 题干与选项直接来源于岗位 SOP 或专家共识
- 有唯一、确定的正确答案
- 无多义性，不含隐性社交推断
- 已通过内容审查（无 SOP 冲突、无安全边界模糊）
- 由内容负责人在 `status = 'ACTIVE'` 时确认

**禁止在 MASTER 上做的操作：**
- 修改 `content_json`（题干/选项文字）
- 修改 `scoring_rule_json`
- 修改 `difficulty_level`
- 任何可能改变构念定义的字段变更

若需更新，走"新增 + 废弃"流程（见第 5 节母题治理规则）。

---

#### TRAINING_VARIANT — 训练变式题

**定义：** 与某道母题"同构念、不同表面"的训练专用题。学员通过反复练习该层题目掌握规则，但不会在正式测评中遇到原样重复题。

**入层判断标准（满足所有）：**
- `parent_question_id` 不为 NULL，指向一道 MASTER 题
- 至少改变以下一个有教学意义的变量：商品/材料、异常形式、呈现方式、提示强度、干扰项
- 不能与其 parent 题表面完全相同（禁止只换数字/单位的机械复制）
- 构念与评分规则与母题保持一致

**典型变式方向（参考 chatgpt建议.md 第三节）：**
- 更换材料：大桶水 → 整箱饮料 → 袋装大米
- 更换异常形式：价签缺失 / 价签歪斜 / 价格不一致
- 调整提示强度：完整示范 → 流程卡提示 → 完全独立
- 增加干扰项：背景噪声、中途打断、任务切换

---

#### GENERALIZATION — 泛化训练题

**定义：** 将某道母题的构念迁移到新情境（跨商品类别、跨岗位、跨场景）的训练题。

**与 TRAINING_VARIANT 的区别：**  
TRAINING_VARIANT 仍在原岗位原情境内变化表面细节；GENERALIZATION 切换到不同情境，检验学员是否能举一反三。

**示例（来自 chatgpt建议.md §四）：**
```
母题 M2-006：先进先出——新旧货复位（超市货架场景）
  TRAINING_VARIANT V1–V5：同货架场景，换批次/日期/品类
  GENERALIZATION G1：办公耗材按入库日期先后使用
  GENERALIZATION G2：餐饮原料按有效期先后摆放
```

**入层判断标准：**
- `parent_question_id` 不为 NULL
- 情境与母题所属岗位有明显差异（不同商品大类或不同物理环境）
- 目标构念与母题一致

---

#### GRADUATION — 结业候选池

**定义：** 专门为结业考核准备的候选题，构念难度与母题一致，但表面已系统性替换，无法通过背诵训练题直接得分。

**与 MASTER 的区别：**  
MASTER 可用于阶段测评；GRADUATION 专属结业，表面特征必须与训练题（TRAINING_VARIANT / GENERALIZATION）完全区隔。

**入层判断标准（chatgpt建议.md §五.1 的结业题控制标准）：**  
相较于同构念的训练题，至少替换以下全部：
- 商品或材料（不能与任何该构念训练题用同一商品）
- 图片和版式（若有视觉媒体）
- 具体数字
- 情境背景描述

目标构念和难度等级必须与对应 MASTER 保持一致。

## 3. 与 question_bank 表的对应关系

### 3.1 新增字段设计

在现行 schema 中，`question_bank` 表需增加以下两个字段：

```sql
-- 新增字段（schema v0.2.0-question-role）

question_role         TEXT NOT NULL DEFAULT 'MASTER'
                        CHECK (question_role IN (
                          'MASTER',
                          'TRAINING_VARIANT',
                          'GENERALIZATION',
                          'GRADUATION'
                        )),

parent_question_id    TEXT REFERENCES question_bank(question_id),
-- MASTER 题此字段为 NULL
-- TRAINING_VARIANT / GENERALIZATION / GRADUATION 此字段指向对应的 MASTER 题
```

### 3.2 字段约束规则

| question_role | parent_question_id | 约束说明 |
|---|---|---|
| MASTER | NULL | 母题无父引用 |
| TRAINING_VARIANT | 必填，指向 MASTER | 父题 status 必须为 ACTIVE 或 ARCHIVED（允许指向已归档母题，但组卷时不选） |
| GENERALIZATION | 必填，指向 MASTER | 同上 |
| GRADUATION | 推荐填写，指向 MASTER | 若无直接母题对应则可 NULL，但需在 content_json 中记录构念来源 |

**需要在 DB 层增加的约束触发器（MVP+1 落地时）：**
1. `MASTER` 题的 `parent_question_id` 必须为 NULL
2. `TRAINING_VARIANT` / `GENERALIZATION` 的 `parent_question_id` 必须不为 NULL
3. `parent_question_id` 所引用题目的 `question_role` 必须为 `MASTER`（不允许变式指向变式）

### 3.3 现有 298 题的迁移方案

MVP+1 时，对所有 `question_id LIKE 'M%'` 的题执行：

```sql
UPDATE question_bank
  SET question_role = 'MASTER',
      parent_question_id = NULL,
      updated_at = datetime('now')
WHERE question_id LIKE 'M%';
```

`Q_BASE_*` 题暂不标记 question_role（保持 DEFAULT 'MASTER'），待基础能力题库分层设计确定后统一处理。

## 4. 与 strategy_config 的联动方式

### 4.1 question_policy_json 新增 allowed_roles

现行 `question_policy_json` 字段控制组卷规则（module 分布、难度权重等）。MVP+1 新增 `allowed_roles` 数组：

```json
{
  "module_distribution": { ... },
  "difficulty_weights": { ... },
  "allowed_roles": ["MASTER"],
  "exclude_exposed": true
}
```

**参数说明：**

| 参数 | 类型 | 说明 |
|------|------|------|
| `allowed_roles` | string[] | 组卷时允许选入的 question_role 值。不填则默认 `["MASTER"]`（向后兼容）。 |
| `exclude_exposed` | boolean | 为 true 时，组卷前排除该学员已曝光的题目（见第 4.2 节）。结业组卷必须为 true。 |

**各场景推荐配置：**

| strategy_type | allowed_roles | exclude_exposed |
|---|---|---|
| BASELINE_ASSESSMENT | `["MASTER"]` | false |
| MOCK_EXAM / 阶段测评 | `["MASTER"]` | false |
| TRAINING_PRACTICE | `["TRAINING_VARIANT", "GENERALIZATION"]` | false |
| GRADUATION（结业）| `["GRADUATION"]` | true |

### 4.2 曝光排除逻辑（GRADUATION 场景）

**曝光定义：** 学员在任何 assessment_session 或 training_session 中，收到过某道题的 question_id（无论是否作答）。

**排除流程（伪代码）：**
```
candidates = SELECT question_id FROM question_bank
             WHERE question_role IN (allowed_roles)
               AND job_code = session.job_code
               AND status = 'ACTIVE'

if exclude_exposed:
  exposed = SELECT DISTINCT question_id FROM assessment_session_response
            WHERE session.student_id 对应的所有历史 session
  candidates = candidates - exposed

paper = 从 candidates 中按 question_policy_json 的 module_distribution 随机抽取
```

**曝光排除的前提数据基础：** 当前 `assessment_session_response` 表已记录 `question_id`，足以支持此逻辑；无需新增表，只需组卷时传入 `student_id` 并查询历史记录。

## 5. 母题治理规则

### 5.1 冻结约束

MASTER 题一旦 `status = 'ACTIVE'`，其内容字段视为冻结：

**冻结字段：**
- `content_json`（题干、选项、正确答案）
- `scoring_rule_json`
- `difficulty_level`
- `question_role`（不允许从 MASTER 变更为其他角色）
- `module_type`（不允许跨模块迁移）

**未冻结字段（允许更新）：**
- `status`（可从 ACTIVE → ARCHIVED 进行退役）
- `media_asset_id`（替换媒体资源但构念不变时）
- `sensory_tags_json`（补充感官标签）
- `version`（随上述合法更新递增）

冻结约束拟在 schema v0.2.0 以 DB 触发器强制执行（优先级：DB 层 > 应用层）。

### 5.2 superseded_by_question_id 字段（MVP+2 考虑）

当母题需要被替换时（如 SOP 更新导致答案变化），流程如下：

1. 新增一道新的 MASTER 题（新 question_id，question_role = 'MASTER'）
2. 旧题执行：`status = 'ARCHIVED'`
3. 旧题的 `superseded_by_question_id` 指向新题（字段待 schema v0.3.0 新增）

**实际意义：**
- 保留历史测评结果中旧题的评分记录（不可删除已参与计分的题）
- 组卷时自动跳过 ARCHIVED 题
- 通过 `superseded_by_question_id` 可追溯"这道题是为了替换哪道旧题"

**当前（MVP 阶段）无此字段，** 旧题退役只需 `status = 'ARCHIVED'`，superseded 关系用 `content_json.notes` 字段临时记录即可。

## 6. 落地路线图

### Phase 0 — MVP（当前，schema v0.1.10）

**状态：**
- `question_bank` 无 `question_role` 字段
- 所有 M1–M6 题实际作为 MASTER 使用，但未正式标记
- 结业/训练/测评的题目区分依赖 strategy_config.question_policy_json 中的 module 分布，无角色过滤

**约束：** 不做 schema 变更，保持 MVP 稳定交付。

---

### Phase 1 — MVP+1（schema v0.2.0-question-role）

**目标：** 完成字段落地，建立角色隔离机制。

**变更清单：**

1. `question_bank` 表新增字段：
   - `question_role TEXT NOT NULL DEFAULT 'MASTER'`
   - `parent_question_id TEXT REFERENCES question_bank(question_id)`

2. 数据迁移：
   - 所有 `M%` 题设置 `question_role = 'MASTER'`
   - `Q_BASE_*` 题暂保持 DEFAULT 'MASTER'

3. `strategy_config.question_policy_json` JSON Schema 更新：
   - 新增可选字段 `allowed_roles`（默认 `["MASTER"]`，向后兼容）
   - 新增可选字段 `exclude_exposed`（默认 false）

4. 组卷逻辑更新：
   - 从 question_policy_json 读取 allowed_roles，加入 SQL WHERE 条件
   - exclude_exposed = true 时，传入 student_id 过滤已曝光题

5. DB 层触发器：
   - 阻止对 ACTIVE MASTER 题的冻结字段进行 UPDATE
   - 验证 TRAINING_VARIANT / GENERALIZATION 的 parent_question_id 不为 NULL
   - 验证 parent_question_id 引用的 question_role = 'MASTER'

**不在此阶段做：**
- 批量新增 TRAINING_VARIANT / GENERALIZATION / GRADUATION 题
- `superseded_by_question_id` 字段

---

### Phase 2 — 变式题扩充（内容工作）

**目标：** 按"变式族"方式，为重点构念补充 TRAINING_VARIANT 和 GENERALIZATION 题。

**扩充优先级（参考 chatgpt建议.md §六）：**
- 优先：安全操作、临期/破损处理、价签异常、FIFO、库存盘点（高频错误 + 高安全关键）
- 其次：货架整理、分类上架（题量易膨胀，需依构念覆盖表控制比例）

**每道母题第一轮扩充目标：** 3–5 道 TRAINING_VARIANT（材料替换优先），不强求一次性补齐。

---

### Phase 3 — 结业候选池建设（MVP+2）

**目标：** 建立完整的 GRADUATION 层，实现真正的"曝光排除式结业组卷"。

**变更：**
- `question_bank` 新增 `superseded_by_question_id`
- 结业策略的 strategy_config 切换至 `allowed_roles: ["GRADUATION"]`
- 组卷引擎实现 exclude_exposed 过滤逻辑
