# [已废弃] 生图会话结束：最小可恢复交接（SVETS 项目专用）

> 本文属于旧图片试跑流程，只作历史追溯。不要继续使用下方 `AIimages/`、旧 seed 或旧会话恢复步骤。当前生产状态记录在 `doc/assets/asset-manifest.json`，新会话使用 `doc/features/visual-asset-prompt-compilation-session-guide.md`。

目标：让下一次生图会话最低成本恢复现场，同时保证“图片文件、标准命名、应用接入位点”三者不脱节。

## 步骤一：更新图片侧当前状态（建议写入 `.continue-here.md` 或本轮回复中）

```md
- <下一步唯一原子动作，例如“将 JDG-MS02 标准图登记为 asset_resource 草案清单”>
```

规则：

- `Next Action` 必须是原子动作
- 必须明确哪些图片是标准版，哪些已废弃
- 必须写清资源接入是“已入库”还是“尚未入库”

## 步骤二：图片文件清理检查

结束前执行：

```bash
ls -1 AIimages 2>/dev/null | sed -n '1,200p'
```

检查项：

1. 同一资产是否还保留 `r2` / `r3` / 时间戳版临时文件
2. 标准文件名是否已指向最终版本
3. 是否存在会误导后续会话的旧版文件

规则：

- 若新标准版已经确认，旧版应删除或明确标记废弃
- 不允许同目录长期并存多套未说明用途的近似同名资产

## 步骤三：资源接入准备检查

如果本轮已经到“接入应用”准备阶段，结束前必须说明以下 3 件事是否完成：

1. 是否已为每个图片产物定义稳定 `asset_id`
2. 是否已定义 `app_uri` 与 `local_path` 的映射方案
3. 是否已明确写到哪类题目字段上：
   - `question_bank.media_asset_id`
   - `content_json.variants[].media_asset_id`
   - `content_json.drag_items[].image_asset_id`
   - `content_json.options[].image_asset_id`

如果任意一项没做，必须显式写 `未完成`，不能默认“后面再说”。

结束前建议至少生成以下清单之一：

### 方案 A：资产登记草案表

```text
asset_id | local_path | app_uri | asset_type | asset_role | target_question_field
```

### 方案 B：题目挂接草案表

## 7. 关于“生成的图片如何正确链接到应用里”

这是图片会话必须持续跟踪的问题，不能等编码会话自己猜。

当前项目的正确链路应遵循以下原则：

1. 图片文件只是落在磁盘上的原始产物，不等于应用已可用。
2. 应用正式引用应经过 `asset_resource`：
   - `asset_id`
   - `asset_type='IMAGE'`
   - `asset_role='QUESTION_MEDIA'` 或更合适角色
   - `app_uri`
   - `local_path`
   - `mime_type`
   - `file_hash`
   - `file_size_bytes`
   - `status='ACTIVE'`
3. 题目挂接时，不应直接写磁盘路径，而应写 `asset_id`：
   - 判断题主图 / 视频：`question_bank.media_asset_id`
   - 判断题正确 / 错误变体：`content_json.variants[].media_asset_id`
   - 拖拽题素材：`content_json.drag_items[].image_asset_id`
   - 单选题选项图：`content_json.options[].image_asset_id`
4. 渲染进程应通过 `asset_resource.app_uri` 访问资源，而不是直接访问 `local_path`。
5. 所有挂接到题目的 `asset_id`，必须满足：
   - `asset_resource` 中存在
   - `status = 'ACTIVE'`
   - hash 校验通过

所以，生图会话的正确终点不是“PNG 已生成”，而是：

```text
PNG 已生成 → 资产已定稿 → 资产已登记 asset_resource → 题目字段已挂 asset_id → 渲染层通过 app_uri 可读
```
