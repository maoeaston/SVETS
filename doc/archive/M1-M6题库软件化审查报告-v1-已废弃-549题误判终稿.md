## 1. 总体结论

| 判断项 | 结论 |
|---|---|
| 是否建议先审完 M1-M6 再最终收口 PRD v1.0.7 | **是**。M1-M6 暴露了 v1.0.7 未覆盖的 3 个结构性缺口（岗位模块维度、视频呈现、5 分制转换），先收口会导致 v1.0.8 再改一次数据合同。 |
| PRD v1.0.7 是否足以承载 M1-M6 | **小修**。question_type / interaction_type / response_status / support / evidence / log 骨架够用；缺口集中在 module 维度、presentation、评分转换规则和专业岗位策略配置，不需要推翻两层题型模型。 |
| 是否建议现在清空数据库重导 | **暂缓**。前置条件见第 9 章：版本口径统一 → v1.0.7-final 收口 → schema v0.1.11 落地 → dry-run 全绿，四项完成前不动库。 |

### 最大 5 个风险点

1. **三份材料版本互相不一致（最高风险）**。PDF「2026.7.3 终稿」实测 **549 题**（M1:96 / M2:65 / M3:108 / M4:70 / M5:104 / M6:106），不是各文档反复引用的 298 题。施测手册 v1.0 的题号体系（M1题48、M2题41、M3题58、M4题48、M5题55、M6题48，合计恰为 298）与 PDF 终稿对不上；手册描述的支架配对题、中断版、干扰版、嵌入观察（碰倒水瓶）、角色扮演（M5题52/54）、门店版/文职版平行卷，在 PDF 549 题中**全部不存在**（关键词零命中）。[需确认]：549 题 PDF 与库内 298 题 CSV、手册 v3.0 三者谁是软件化基线，还是「549 为原始素材池、298 为精选版」。口径不定，任何字段映射和清库重导都不能启动。
2. **module 维度无落点**。`question_bank.module_type` CHECK 只允许 6 个基础能力枚举（FINE_MOTOR…SAFETY_OPERATION），而 M1-M6 是岗位任务模块（货架整理/拆箱补货/临期分拣/库房盘点/突发应对/识别分类）。现库 298 题是如何塞进 6 个能力枚举的 [需确认]。v1.0.7 的 `question_policy_json.online_quota_by_module` 也只认 6 个能力模块，专业岗位测评无法按 M1-M6 组卷。
3. **计分制系统性冲突**。549 题全部为 5 分制，且大量使用扣分粒度（扣 0.5/1/2/3 分、扣完为止）；线上合同是 0/2、线下是 0/1/2。手册的「五类分数分开报告」（操作分/知识分/支架指数/注意执行指标/社交元认知编码）与现有 ABILITY_SCORE / TRAINING_COMPLETION / OPERATION_PASS_RATE 三分离模型也不对齐。5 分制→0/2 与 5 分制扣分→0/1/2 rubric 的转换是内容工作+专业审查，不是导入脚本能自动做的。
4. **答案键与应答定势问题**。抽查发现疑似答案错误：M3题90（"剩余20天到期零食无需标注临期可随意摆放"，键标"正确"）、M3题96（"包装扁扁的薯片可以正常售卖"，键标"正确"，与 M2/M3 破损判定规则自相矛盾）。M5 情境选择题正确项高度集中在 B 选项（应答定势风险，手册第三章自己也警告了方向定势）。未经逐题答案键审计与专业确认，不得转 ACTIVE——这正是 v1.0.7 第 56 条约束的适用场景。
5. **判断题依赖视频、实物题依赖 rubric 细则，两者当前合同都接不住**。164 道判断题的设计说明是「视频展示理货员做正确/错误操作」，但 `presentation_type` 枚举无视频项、asset role 无视频角色；90 道实物题的计分规则在 PDF 里只有一句话，不满足 v1.0.7 对 OFFLINE_OPERATION 的条件必填（offline_tool_brief、标准材料规格、终止条件），标准材料/指导语在手册附录 C/E 中，但附录未随包交付 [需确认]。

## 4. 逐类题目改造建议

按题目类型归为 9 类（不逐题重写）：

### 4.1 三选一图文选择题（约 208 题，全模块）
| 项 | 建议 |
|---|---|
| 典型例子 | M1-1～30、M2-1～20、M6-1～36 |
| question_type / interaction | SINGLE_CHOICE / SINGLE_SELECT |
| presentation_type | IMAGE_CARD（场景图+3 选项图） |
| answer_shape | `{ selected_option_id }` |
| scoring_rule | EXACT_MATCH（选X得5分→0/2 直转，无损） |
| 必需素材 | 场景图 ×1 + 选项图 ×3，全部走 assets[]（role: SCENE_IMAGE / OPTION_IMAGE） |
| 行为日志 | 通用字段 + first_selection_latency_ms、change_count |
| 证据类型 | 知识类→SOFTWARE_BEHAVIOR；情境类→SITUATIONAL_JUDGMENT |
| 效度边界 | "图片判断不等于真实岗位操作达标"（合同已有模板） |
| 可进正式测评 | 可（答案键审计+专业确认后） |
| 更适合的层 | 大量同构念表面变体题（如 M1-3/17/19 同为摆放规范）应在分层时拆为 1 母题 + N 训练变式，不应全部进正式池 |

### 4.2 判断题（约 164 题，全模块）
- 推荐 TRUE_FALSE / BINARY_SELECT；`{ selected: boolean }`；EXACT_MATCH。
- **呈现方式是本类唯一障碍**：设计稿要求视频演示。MVP 建议统一降级为 IMAGE_CARD（正/误操作对比图），`source.transformation` 记 "视频演示降级为静态图"。[需确认]
- 风险：正确/错误键分布需 dry-run 统计（防定势）；疑错题（M3-90、M3-96）必须专业复核。
- 大量表述雷同题（M1-51～80 与选择题构念重复）更适合 TRAINING_VARIANT 层。

### 4.3 拖拽排序流程题（约 50 题）
- DRAG / ORDERING；`{ ordered_item_ids }`；ORDER_MATCH；2～5 步。
- 素材：步骤卡图 ×N（role: DRAG_ITEM_IMAGE）。日志：ordered_item_ids、correction_count、wrong_order_count。
- 手册的"支架版/无支架版配对"（支架指数）在 PDF 版不存在；若引入，支架版属训练变式或需 variant_group_id 配对，**不要**在 MVP 用两道正式题伪装配对设计。
- 可进正式测评：可。

### 4.4 拖拽分类题（约 37 题）
- DRAG / DRAG_DROP；`{ placements: [{item_id, zone_id}] }`；MAPPING_MATCH。
- 素材：待分类项图 + 分区图（DRAG_ITEM_IMAGE / DROP_ZONE_IMAGE）。
- 可进正式测评：可。

### 4.5 日期计算/临期判断链（M3 选择题子集，如 题97/107/108）
- SINGLE_CHOICE / SINGLE_SELECT + IMAGE_CARD（真实版式日期标签素材，手册第三章要求三种版式）。
- **特殊点**：部分题含"不清楚/不确定，需要查询"选项，手册将其定义为元认知诚实信号"不算错"。0/2 合同下必须显式决策：(a) 选"不清楚"记 0 分但在 log_metrics 记 `unsure_selected` 供报告解释；(b) 该类题不进正式池只进观察。**建议 (a)**。[需确认]
- 手册的"日期计算链准入门槛"（题5-7 过→单品效期、题9-10 过→批量巡检）是报告解释逻辑，落 Post-MVP 专业岗位报告，MVP 只保证 sub_module 标注可供后续聚合。

### 4.6 复合情境 SJT（M5 选择题 49 题 + M4 突发应急子集）
- SINGLE_CHOICE / SINGLE_SELECT；证据类型强制 SITUATIONAL_JUDGMENT。
- 效度边界必填："情境选择只证明风险识别与流程判断，不证明现场会做"（对应手册知行分离原则、v1.0.7 约束 47）。
- 正确项 B 偏置需在导入 dry-run 输出选项分布统计并由内容侧打散。
- 可进正式测评：可，但报告解释受限。

### 4.7 限时/计数类任务（少量：M6-101 限时分类、M6-93/100 计数、M4 账实核对）
- 若软件化：SOFTWARE_TASK / TIMED_TASK（SUSTAINED_ACTIVITY）或 TASK_SEQUENCE；METRIC_THRESHOLD（correct_count GTE、超时判定）。
- 日志：planned/active_duration_ms、completed_count、correct_count、error_count。
- 注意约束 46：慢≠低能力，超时判 0 必须是 scoring_rule 显式定义的目标构念。
- 这些题实物版保留线下更符合原设计；软件版建议作为 GENERALIZATION/训练用途，MVP 不强行双轨。

### 4.8 实物操作题（90 题，各模块 15 道）
- OFFLINE_OPERATION / OFFLINE_RUBRIC；教师 0/1/2。
- **必做转换**：5 分制扣分规则（含 0.5 分粒度）→ 0/1/2 三档行为锚点描述，属内容工作+专业审查，导入表须保留原计分规则文本备查。
- 条件必填：offline_tool_brief（迷你货架、道具商品、预制破损样品、日期标签、送货单等，手册第三章有清单）、标准指导语（附录 C [需确认是否交付]）、终止条件。
- M5 的 15 道安全应急实物题（火情、碎玻璃、货架倾倒、受伤处置）：`safety_sensitive = 1` + `professional_review.required = true` + termination_policy 安全停止条件。
- 可进正式测评：可（线下轨道）；不可软件化替代。

### 4.9 口语/沟通反应题（M6-96/103 说出理由；M5 顾客对话类）
- 保留线下教师评分（OFFLINE_RUBRIC），或软件化为 BRANCHING_TASK + 消息卡（AAC 兼容），validity_boundary 注明"消息卡降低自主语言生成要求"。
- 禁止语音自动判分（合同附录 B 已排除）。
- 手册版角色扮演（M5题52/54 逐字台词）与嵌入观察（碰倒水瓶、模糊指令）：**不软件化**；若保留，见第 5 章。

## 6. 是否需要提前引入题库分层

结论：**MVP 必须在 schema v0.1.11 预留字段，但不激活组卷逻辑。**

理由：v0.1.11 是全量重建基线（不做原地 migration）。若不预留 `question_role` / `parent_question_id`，MVP+1 引入分层时要再出 v0.1.12 并再次清库或迁移；两列 + DEFAULT 的预留成本接近零。这与 v1.0.7 "MVP 不新增 parent_item_id" 不冲突——parent_item_id 是 testlet 复合题概念，parent_question_id 是变式母题指针，两者语义不同，但 PRD 应明确区分以免 Codex 混淆。

| 项 | MVP | Post-MVP | 说明 |
|---|---|---|---|
| `question_role` 列（DEFAULT 'MASTER'，CHECK 四枚举） | **必须**（仅预留） | 组卷过滤激活 | M1-M6 导入即标 MASTER，满足母题冻结治理前提 |
| `parent_question_id` 列（可空，自引用 FK） | **必须**（仅预留，全部 NULL） | 变式题写入时激活三条触发器约束 | 触发器（MASTER 必 NULL / 变式必非 NULL / 父必为 MASTER）可 MVP 一并建，成本低 |
| `allowed_roles`（question_policy_json v1.1 可选字段，默认 `["MASTER"]`） | **建议**：只在 JSON 合同和 validator 中定义默认值 | 组卷 WHERE 条件激活 | 保证历史策略向后兼容 |
| `exclude_exposed` / `exposure_count` | 否 | 结业组卷时实现 | 曝光可由 assessment_session_question 历史查询派生，**不建曝光计数列**（避免冗余状态） |
| TRAINING_VARIANT / GENERALIZATION / GRADUATION 题内容 | 否 | Phase 2/3 内容工作 | 与分层文档路线一致 |
| MASTER 冻结触发器 | v1.0.7 §11.12.1 冻结规则已覆盖（被引用后不可改） | ACTIVE 即冻结的更强规则 | 分层文档要求 "ACTIVE 即冻结"，v1.0.7 是"被 session 引用后冻结"，两者口径不一致，PRD 需二选一 [需确认，建议取分层文档的更严口径] |

最低预留（若决策连字段都不加）：至少在 `content_json.source` 增加 `candidate_role` 字符串字段记录分层意图，保证后续 UPDATE 迁移可脚本化。但不推荐——列级预留更干净。
