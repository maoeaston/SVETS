## 1. 总体结论

| 判断项 | 结论 |
|---|---|
| 先审完 M1-M6 再收口 PRD v1.0.7 | **是**。298 条暴露了 v1.0.7 的 4 个真实缺口（岗位模块维度与混池隔离、线下观察项通道、判断题视频呈现、施测变体结构化），先收口必然返工。 |
| v1.0.7 是否足以承载 M1-M6 | **小修**。好消息：298 条纸面题不需要 SOFTWARE_TASK 新交互（SC/TF/DG 三类合同全覆盖），比基础能力 v0.2 题库对合同的压力小。缺口集中在线下侧与库隔离，不动两层题型模型。 |
| 是否清空重导 | **是，但暂缓执行**。重导不可避免：① 298 条是旧合同结构（expected_answer 在 content_json、无 evidence/support/log 合同）；② 数据损坏（ability_tags/note）；③ 295 条在无素材、键未审计情况下 ACTIVE，违反 v1.0.7 全部门禁。前置条件见第 9 章。 |
| 549 ↔ 298 关系判断 | 见第 2.5 章。**以 298 为唯一改造基础，不从 549 补回构念进正式池**；549 是训练变式（TRAINING_VARIANT）的现成素材池。 |

### 最大 5 个风险点

1. **混池风险（最高、且是现库活风险）**。298 条以 `job_code=supermarket_stocking` + 6 个基础能力 module_type + TRUE_FALSE/SINGLE_CHOICE/DRAG + status=ACTIVE 存在。若基础能力 Q_BASE_* 题使用相同 job_code [需确认]，现行组卷 SQL（按 job_code+module_type+question_type+status 过滤）**可能把 M1 货架题抽进基础能力测评卷**。无论确认结果如何，v1.0.7-final 必须给出岗位库与基础能力库的显式隔离手段（见第 3 章 question_policy 行与第 8 章补丁 2）。
2. **module_type 机械映射语义错误**。M4 库房盘点→EMOTION_REGULATION、M6 商品分类→BASIC_SOCIAL 是纯凑数映射，一旦按模块出报告（module_profiles 按 6 能力模块命名），会输出"情绪调节=库房盘点得分"这类错误结论。岗位模块维度需要自己的落点。
3. **线下侧合同缺口成为主要矛盾**。100/298（34%）是线下条目：97 道实操 + 3 道嵌入观察。现状三处断裂：① rubric 无三档行为锚点（不满足现行共享类型，更不满足 v1.0.7）；② 嵌入观察被存成"OFFLINE_OPERATION + RUBRIC_BASED max_score=2"，与其自身"不计分-单独编码"文本自相矛盾，而 v1.0.7 的 OBSERVATION_ONLY 仅定义了 `SYSTEM_DERIVED_OBSERVATION`（软件事件派生），**没有线下人工观察的合法通道**；③ 支架/中断/干扰/预埋/限时/角色扮演等施测变体全靠自由文本 note/source_ref 承载，无结构化字段，无 variant_group_id。
4. **素材与呈现全缺口**。0/298 有资产；68 道判断题全部设计为视频呈现，presentation_type 无视频枚举。必须做"MVP 图片降级 vs 引入 VIDEO_SCENE"决策，且素材制作（≥200 条 media_brief 兑现）是清库重导前最大的内容工作量。
5. **答案键与选项分布问题**。M1_TF_015 疑似键错（正向组孤例 false）；SC 正确项 C 位仅 7/96；线上二值 0/2 虽与 EXACT_MATCH 兼容可直转，但**未经逐题键审计不得 ACTIVE**（v1.0.7 约束 56 的直接适用场景）。

## 4. 逐类题目改造建议（9 类，覆盖 298 条）

### 4.1 单选题（96 条，`M?_SC_*`）
- SINGLE_CHOICE / SINGLE_SELECT；IMAGE_CARD（有配图时）或 TEXT_ONLY；`{ selected_option_id }`；EXACT_MATCH 0/2（现库规则可直接沿用）。
- 素材：场景图 + 选项图（media_brief 兑现）；日志：first_selection_latency_ms、change_count。
- 证据：知识类 SOFTWARE_BEHAVIOR；情境类（M5 全部 20 条、M4 突发子集）SITUATIONAL_JUDGMENT。
- 效度边界：图片判断 ≠ 实操达标。可进正式测评（键审计 + C 位偏置修订后）。

### 4.2 判断题（68 条，`M?_TF_*`）
- TRUE_FALSE / BINARY_SELECT；`{ selected: boolean }`；EXACT_MATCH。
- **视频决策是唯一阻塞**（68/68 media_brief 为视频）。建议 MVP 降级为正/误操作对比图。
- 正向/反向/映射反例分组信息保留到 `source.origin_refs`；键审计重点：M1_TF_015。
- 映射反例组（12 条，"当场直接处理没请示"类陷阱泛化题）：证据类型 SITUATIONAL_JUDGMENT，报告解释对应手册"陷阱题专项检查"，MVP 只需 sub_module 标注可聚合。

### 4.3 拖拽排序题（约 28 条，`M?_DG_*` 中 zones 为"第 N 步"者）
- DRAG / **ORDERING**（现库用 DRAG_DROP+zones 模拟排序，重导时转 ORDERING）；`{ ordered_item_ids }`；ORDER_MATCH。
- **支架版配对**（6 条标注"支架分差=第Ⅲ类指标"）：现库把"支架版/无支架版"塞在一条题的 note 里。手册要求分差 = 两次施测 → **必须拆为两题**，`variant_group_id` 配对，支架版 `interaction.config.prefilled_placements` 锁定首步 [需确认拆分口径]。支架版建议 item_usage=SCORED_ITEM 但仅训练/诊断用途（不进正式池），或两题都进但报告只算分差——需专业定稿。

### 4.4 拖拽分类题（约 6 条，如 M5_DG_036、M6_DG_027）
- DRAG / DRAG_DROP；`{ placements }`；MAPPING_MATCH。M5_DG_036"自己处理/立即上报"分类是 SJT 性质，证据 SITUATIONAL_JUDGMENT。

### 4.5 标准实操题（约 80 条，`M?_OP_*` 常规项）
- OFFLINE_OPERATION / OFFLINE_RUBRIC；教师 0/1/2。
- **必做**：逐题把现有 rubric_criteria（仅一句话/条）扩成三档行为锚点（criterion 级 0/1/2 描述），现库通用"未能完成/部分完成/完全达标"不合格。
- offline_tool_brief 现库质量尚可（如"迷你货架 1 组；5 件实物商品"），需补终止条件与标准指导语（手册附录 C [需确认是否交付]）。

### 4.6 施测变体实操题（10 条：中断版 4、干扰版 1、预埋差错 3、限时 2）
- 仍 OFFLINE_OPERATION；新增结构化施测配置（建议 `content_json.administration`）：中断时点/标准中断语/恢复编码维度（A 接续/B 部分重做/C 完全重做/D 需提示）、环境音文件+分贝、预埋位置引用（密封材料资产）、限时时长与可视沙漏规则。
- 恢复编码/检出-报告编码是**观察数据不是分数**：进线下评分记录的观察字段（answer/offline payload），不改变 0/1/2 rubric 本身。

### 4.7 角色扮演题（5 条：M5_OP_044/051/052/054 等）
- OFFLINE_OPERATION / OFFLINE_RUBRIC + `professional_review.required=true`；标准台词脚本（附录 D）作为 OFFLINE_TOOL_GUIDE 资产；双人施测要求写入 standard_instruction。
- 现库 rubric 内嵌手册 5 分制"话术 1/找人 2/交接 2"，与 scoring JSON 的 0/1/2 冲突——三步计分转三档锚点需专业定稿 [需确认]。
- 报告边界：只解释"脚本具备/启动需支持"，不外推现场应对。

### 4.8 嵌入观察项（3 条：M1_OB_048、M5_OP_048、M5_OP_055，现均 DRAFT）
- 转 `item_usage=OBSERVATION_ONLY` + `scoring_type=NO_SCORE` + 线下观察通道（第 3 章 item_usage 行的 (a)/(b) 决策）。
- 现库矛盾必须修复：文本"不计分"但 scoring max_score=2。
- 需要字段：非预告标记、知情同意条款引用、事后告知流程、编码维度（扶起清理/口头提醒/注视无动作/未注意等）。不进组卷、不进 42+8、不进完成率——v1.0.7 既有规则直接适用。

### 4.9 文职平行版（6 条：M4_OP_043-048）
- OFFLINE_OPERATION；与对应门店版 `variant_group_id` 配对（门店-文职分差是安置环境决策数据）。
- MVP 只保证配对数据可查询；"分差>15% 推荐文职岗"的解释逻辑 Post-MVP。
