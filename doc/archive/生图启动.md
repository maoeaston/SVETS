# 生图会话启动：恢复现场（SVETS 项目专用）

当前阶段允许读取文档、检查 Git 状态、查看已有图片资产与批量计划文件。  
如本轮目标只是继续已有生图链路，**不要先改代码**，先确认资产基线、命名和接入位点。

---

## 步骤一：按顺序读取

1. `AGENTS.md` — 架构原则、题库 / 资源约束、沟通规则
2. `.continue-here.md` — 如果本轮与编码会话有依赖，先确认当前编码会话进度
3. `doc/features/question-bank-image-plan.md` — 当前图片资产总方案
4. `doc/features/question-bank-image-batch-plan-v001.json` — 全量批量计划
5. `doc/features/question-bank-image-batch-pilot-v001.json` / `doc/features/question-bank-image-batch-pilot-acceptance.md` — 若当前在试跑验收阶段

如果 `.continue-here.md` 或用户明确提到额外图片规划文档，再补读。  
不要主动扩读实现文档，除非本轮任务涉及“图片如何接入应用”。

---

## 步骤二：检查 Git 现场

```bash
git stash list
git status --short --branch
git log --oneline -5
```

规则：

- 只列出 stash，不要自动 pop
- 当前有其他 agent 在并行编码时，不得碰与代码实现直接相关的脏文件
- 如果当前在 `main` 且有未提交代码改动，默认只做文档 / 资产侧工作，不介入代码文件

---

## 步骤三：检查图片现场

优先执行：

```bash
ls -1 AIimages 2>/dev/null | sed -n '1,200p'
rg -n "JDG-|DRG-" doc/features/question-bank-image-*.md doc/features/question-bank-image-*.json
```

目标：

1. 确认当前已落盘的图片资产有哪些
2. 确认是否存在 `r2` / `r3` 等临时版本未清理
3. 确认标准名资产是否已覆盖旧版
4. 确认本轮是“继续试跑”还是“开始新资产批次”

---

## 步骤四：检查资源接入位点（如本轮涉及“接入应用”）

必须确认以下事实，不要靠记忆：

1. `asset_resource` 是资源正式登记表  
   参考：`src/main/db/schema.sql`
2. 渲染进程理论上应通过 `asset_resource.app_uri` 使用资源，而不是直接硬编码磁盘路径  
   参考：`src/main/db/schema.sql`
3. 题目资源挂接位置：
   - 判断题 / 单选题主媒体：`question_bank.media_asset_id`
   - 拖拽题子素材：`content_json.drag_items[].image_asset_id`
   - 单选题选项图：`content_json.options[].image_asset_id`
   - 判断题变体：`content_json.variants[].media_asset_id`

如果这些位点未确认，本轮不得输出“接入完成”类结论。

---

## 步骤五：输出启动确认摘要

固定用以下格式，不要加额外说明：

```text
当前生图任务：
当前阶段：方案规划 / 小批次试跑 / 批量正式出图 / 资源接入准备
当前分支：
下一步唯一原子动作：
相关文件：
是否存在 stash：
最近提交：
Repo 状态：clean / dirty / stashed
当前图片基线：
资源接入位点：
```

字段说明：

- `当前图片基线`：写当前要沿用的标准资产组，例如 `JDG-MS02 / JDG-MS04 / DRG-BG01 / DRG-OBJ02`
- `资源接入位点`：写本轮涉及的接入字段，例如 `question_bank.media_asset_id / content_json.drag_items[].image_asset_id`

---

## 步骤六：遇到以下情况先停止并说明

- `.continue-here.md` 与当前生图方案明显冲突
- `AIimages/` 中存在多套同名资产但未说明哪套是标准版
- 生图批量计划中的标准名与本地图片实际文件名不一致
- 用户要求“接入应用”，但当前还没确认 `asset_resource` / `question_bank` 的接入字段
- 编码 agent 正在改资源接入相关代码，而本会话没有明确授权介入

完成以上检查后，如无冲突，再进入生图或文档更新阶段。
